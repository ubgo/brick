# Changelog

All notable changes to `github.com/ubgo/brick` are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versioning is [SemVer](https://semver.org/) with the pre-GA convention that `v0.x` may break.

## [Unreleased]

Nothing is tagged yet. This section records what the first release will contain.

### Changed (breaking)

- Exported package variables that any importer could mutate for the whole process are now functions returning a fresh value: `brick.DefaultRoots` is `brick.DefaultRoots()`, `brick.DefaultImageDirs` is `brick.DefaultImageDirs()`, `brick.DefaultImageWidths` is `brick.DefaultImageWidths()`, and in `contrib/states-sql` `statessql.Postgres`, `statessql.SQLite` and `statessql.MySQL` are `statessql.Postgres()`, `statessql.SQLite()` and `statessql.MySQL()`.

### Added

#### The render engine (v1)

- Pages, layouts and components are `.html` files with optional YAML frontmatter. A component is a tag, `<Card>` or `<x-card>`, resolved from component roots, with typed props (`type`, `default`, `required`, `oneof`), boolean and expression attributes (`:count="5"`), and undeclared attributes collected for `{{ attrs }}`.
- Children and blocks: `{{ children }}`, named `<brick:prop>` blocks read with `{{ node }}` / `{{ hasNode }}`, scoped slots through `.Slot`, `.Children` to inspect child tags, raw bodies (`raw: true`) and `src=` for code shown from a file.
- Whole-page transpile: a page becomes one Go template, so `{{ range }}` can wrap a component tag and every `{{ }}` is Go's own `html/template` with its escaping unchanged.
- Context (`.Ctx`) with `provide` and `inject`, a read-only `.Site`, data files, translations with plural rules and localized dates, boundaries with fallbacks, and dynamic components chosen by name.
- Sandboxed scripts through the `Scripting` interface, with Starlark in `contrib/script-starlark`: inline `<brick:script>` functions, `.star` modules and loaders, step and time limits, and `db` / `http` capabilities that the host grants explicitly. SQL must be a literal.
- Component styles and client modules: `<brick:style>` (global or `scoped`), `<brick:client>` modules delivered once per component type with subresource integrity, `{{ assets }}`, and CSP nonces.
- `brick check` diagnostics with file and line for every problem at once, including warnings for the traps (`open="false"`, conditional children).
- `bricktest` for theme tests with golden files; adapters for goldmark markdown, bluemonday sanitizing and serving assets over HTTP.

#### The site layer (v2)

- The `site` package: every page gets a URL, `.Site.Pages` for index pages, markdown pages, content collections with required fields, a render cache invalidated by the files a page read, and static export.
- A polling, content-hashing file watcher (`watch`) and a dev server with live reload and a component playground (`/_brick/play/Card?title=Hi`).
- The `brick` CLI: `check`, `routes`, `serve`, `build` and `vendor`.

#### Tailwind and images (v2.1)

- `tailwind`: the standalone Tailwind binary runs only when a class in the project's files actually changed.
- The `image` built-in: resized 480/960/1440-pixel copies in pure Go with `srcset`, served under content-hashed names; paths from data are confined to real images under `static/`.

#### Islands and the mount runtime (Phase 1)

- Islands: `brick: {island: true}` components render per request inside a cached page, with request values from `site.Options.Request`.
- A ~2 KB browser runtime: `brick.mount(type, fn)` runs a component's client code for every element on the page and every one inserted later, and runs its cleanup on removal. Client modules can import each other.

#### Navigation without reloads (Phase 1.5)

- `navigation: true`: internal links and forms fetch the next page and morph only what changed, with prefetch, a snapshot cache for back and forward, `brick:persist` for elements that must survive a navigation, and a full-page fallback whenever anything goes wrong.

#### Actions (Phase 2)

- Stateful components: `state:` in frontmatter, Starlark actions called by `brick:click`, `brick:submit` and `brick:change`, and the component re-rendered and patched in place. State stays on the server behind a random handle and token; `[state, errors]` returns validation errors for one render; `brick:loading` and `brick:poll`.

#### Bindings (Phase 3)

- `brick:model` (with `.lazy` and `.debounce`), `brick:text` and `brick:show`: form fields update state as the visitor types, and bound text follows instantly without a request.

#### Remote components (v3)

- `use:` imports a component from a repository at a version (`github.com/acme/kit/components/Card.html@v1.2.0`). `brick vendor` fetches imports transitively into `brick_modules/` and pins every file's sha256 in `brick.lock`; `brick vendor -check` verifies offline. Rendering never touches the network.

#### Component libraries (v4)

- `libraries:` in `brick.yaml` (or `brick.Options.Libraries`) makes a whole component library usable by name on every page, with no `use:` in each file and nothing copied. A library is a folder with a `brick-library.yaml` manifest, and it comes from one of four places: a name the host offers (the brick CLI offers the kit as `brick-kit`), a repository at a version (`github.com/acme/ui@v2.1.0`, fetched with `brick vendor` and pinned in `brick.lock`), a folder of the project (`~/ui`), or a single component imported with `use:` as before.
- The project always wins a name: `use:` first, then the project's own component folders, then libraries in the order listed. Every shadowed name is logged, naming both files. `prefix:` keeps two libraries' components apart (`<AcmeButton>`) and `only:` takes a subset.
- Inside a library, `~/` means the library's own root, so a library works copied, vendored, embedded or nested, and can never read the project that uses it.
- A manifest's `global:` links a component's CSS and JavaScript on every page that uses the library, so a kit's design tokens need no `<Theme />` line in the layout.
- Go packages can embed a library and export it as a `brick.Library`; `Config.Apply(&opts, libs...)` offers such libraries to `brick.yaml` by name. The kit is published both ways: `github.com/ubgo/brick/kit@main` and the `github.com/ubgo/brick/kit` package with `kit.Library()`.

#### Hosting under a path

- `site.Options.BasePath` and `-base` on `brick build` and `brick serve` host a site under a path such as `/docs/`, with root-absolute URLs in served and exported HTML rewritten. `site.Mount` and `site.ListenAndServeAll` serve several sites from one server. The engine is unaware of mounting, so an unmounted site renders byte-for-byte as before.

#### The component kit, showcase and demo apps

- `kit/`: more than 130 components covering foundations, actions, forms, data display, feedback, overlays, navigation, layout, charts and mockups. Every component is complete HTML without JavaScript, themed by `--bk-*` tokens with light and dark modes and seven accents, and used as a component library by name (`brick-kit`, `kit.Library()` or the remote `github.com/ubgo/brick/kit@main`). Authoring rules are enforced by a lint test.
- `examples/ui`: a showcase with a documented page and live examples for every component, getting-started guides, and twelve demo apps built only from the kit on SQLite: contacts, invoices, a task board, a dashboard, an inbox, a store, chat, a calendar, a blog CMS, settings, sign-in and a landing page.
- Browser suites in headless Chrome for the engine demo, the showcase and both mounted on one server, and an axe-core accessibility audit.

#### State that survives a restart, and pluggable actions (v5)

- Sealed state: `brick.NewSealedStates` seals a stateful component's whole state into the page (AES-256-GCM under a per-blob HKDF subkey), bound to its store and session, so open pages keep working across a restart, a deploy or a second server with no shared store. `brick keygen` prints a key; `brick serve` and `brick build` read keys from `BRICK_SECRET` (comma-separated, newest first), and `site.Options.StateKeys` takes a `brick.KeyRing`.
- Pluggable state stores built from small pieces: `Codec` (`JSONCodec`, the stable v1 encoding), `Sealer` (`NewAESGCMSealer`), `KeyRing` (`StaticKeys`, `KeysFromEnv`), `BytesStore` wrapped by `brick.Bytes` (optionally encrypted at rest), and the optional `Revoker`, `Lister` and `Pruner` upgrades. `Options.StateStores` plus `brick: {store: name}` let one component keep its state elsewhere; an unknown store name is a compile error. The `statetest` package is the conformance suite for any store, sealer, codec or key ring.
- Session binding (`Options.Sessions`, `WithSession`, `Engine.RevokeSession`): an action from another session finds the state "not found", so signing out ends live components.
- An action middleware chain (`Options.ActionMiddleware`, `ActionFunc`, `ActionMiddleware`) and the `actionmw` package: `Slog`, `RateLimit` with a `Limiter` and an in-memory token bucket, `RequireSession`, `Timeout` and `Recover`. `Options.ActionRequest` gives every action the live request's values, so it sees the user signed in now; `Options.ActionErrors` and `Options.MaxActionBytes` replace the error envelope and size cap.
- Lost state is recovered in place: the runtime fetches a fresh render, morphs the component in, replays what the user typed and runs the failed action once, instead of reloading the page. Actions on one component run one at a time, in order. A store outage answers 503, never 410.
- The `$toggle` built-in action, beside `$set` and `$refresh`, callable from `brick:click`.
- `Options.Funcs` adds Go template functions and `Options.PropTypes` adds prop types, both checked against the built-ins at `New`.

#### Effects and events between components (v6)

- Action effects: besides returning state, an action records small typed effects the runtime applies after the morph — `dispatch`, `redirect`, `navigate`, `flash`, `title`, `download` and `url` — through the Starlark `brick` module (`brick.dispatch("contact-deleted", {"ids": [42]})`, `brick.flash("Saved", "success")`, …) or, in Go, `brick.EffectsFrom(ctx)` with `Effects.Add` for custom `x-*` kinds. Effects exist only while an action runs, an action that fails sends none, and data is JSON only.
- `Engine.RunAction` returns `ActionResult{HTML, Version, Effects}`, so middleware and hosts read effects without parsing markup. The runtime asks for them with `Accept: application/vnd.brick.action+json` and gets a JSON envelope; any other client still gets plain HTML.
- Events between components: a stateful component listens with `brick: {on: {contact-deleted: $refresh}}` (keys may be templates such as `"contact-updated.{{ .Props.id }}"`), a parent hears one child with `<Child brick:on:saved="reload" />`, and markup dispatches without a request with `brick:click='$dispatch("name", {...})'`; `$parent.fn` calls the stateful component around this one. Listener calls are checked at compile time and run as ordinary actions with their own handle and token. The runtime delivers in document order, skips the sender, folds identical waiting listener jobs, and stops chains at 4 hops, a repeated name or 50 listeners.
- Runtime: `brick.dispatch(el, name, data, {to})`, `brick.effect(kind, fn)` to handle or replace an effect kind, a default flash display used only when nothing listens to `flash`, and flashes carried across `navigate` and `redirect`.
- `Options.MaxEffectBytes` (32 KiB per action) and `Options.RedirectHosts` (empty: redirects, downloads and URL changes stay on the request's own host).
- `bricktest.Live`: fill a page, `Call` actions on its stateful components, `Deliver` their events the way the runtime does, and check effects with `AssertDispatched`, `AssertNotDispatched`, `AssertFlash`, `AssertRedirect`, `AssertNavigate`, `AssertNoRedirect`, `AssertTitle`, `AssertDownload` and `Effects`.
- Kit: `Toaster` shows every `brick.flash` as a toast of the flash's level.
- Nested stateful components keep their state when their parent acts: the runtime sends the parent's direct stateful children (`ActionRequest.Children`, handle and token by `data-brick` id), the re-render writes `<brick-keep data-brick="…">` in their place, and the morph keeps the existing element. `reactive: true` on a prop re-renders a kept child, state kept, when the parent passes a different value; the child's handle is then loaded and checked like an action's (store, session, token, same component at the same position) and a handle that does not verify renders the child fresh. Dev warns about a stateful child repeated in a `range` without `key=`. `bricktest.LiveRoot.Call` sends and splices children the same way.
- Demo: the Contacts app flashes instead of keeping toast fields in state, dispatches `contact-added` / `contact-deleted`, builds every element id from its instance id so two copies can share a page, and a new `ContactCount` in the top bar follows those events.

#### Forms (v7 batch A)

- `brick:model.defer`: a field updates the page at once and sends nothing; its value rides, as `sets: [[path, value], …]`, on the component's next request of any kind (click, submit, key, listener, poll). The server applies every entry through the `$set` gate before the action, all or nothing, in one version bump; held values are cleared only by a 2xx answer, and recovery replays them in one request. `ActionRequest.Sets` and `ActionCall.Sets` (`FieldSet`) let middleware read, drop or rewrite entries.
- Lists and nested paths: a checkbox group bound to a list field binds as the list of checked values (one box included) and `<select multiple>` as a list, guided by the engine-written `data-brick-arrays`; `brick:model`, `brick:text`, `brick:show`, `brick:dirty`, `$set` and `sets` take dotted paths (`address.city`, `items.0.qty`) to keys that exist and indices in range, coerced to the current value's type.
- Modifiers: `brick:model.throttle.<n>ms`; `.once`, `.debounce.<n>ms` and `.throttle.<n>ms` on `brick:click`, `brick:submit`, `brick:change` and the new `brick:keydown` (one key from `enter escape tab space up down left right backspace delete`, and `.window`).
- Loading: `brick:loading="save delete"` targets actions, `.delay[.<n>ms]` and `.remove`; `data-loading` on the trigger and its form, and the in-flight action names on the component's element; `brick:disable-with="Saving…"`; polls are quiet unless a `brick:loading` names `$refresh`.
- `brick:dirty[="paths"]` (and `.remove`), `data-dirty`, and `dirty` / `clean` events on `brick.on`; `<button type="reset">` drops held values and resyncs with one `$refresh` only when a live `$set` already reached the server.
- `brick:confirm="…"` asks before an action through one replaceable confirmer, `brick.confirmWith(fn)`; the default is `window.confirm`, and on a page with a kit `ConfirmDialog` its script registers the kit's alert dialog instead (`data-confirm-label` names the button).
- `brick:poll.<interval>="action"` runs an action, `.visible` polls only on screen, and a poll may sit on any element inside the component.
- Compile-time grammar (`grammar.go`, mirrored into `runtime.js` and compared by a test): an unknown or repeated modifier, `.defer` with `.lazy`/`.debounce`/`.throttle`, `.debounce` with `.throttle`, two keys, a missing duration, an undeclared first path segment in `brick:model`/`text`/`show`/`dirty`, a `brick:loading` name that is not an action, and a malformed `brick:poll` are errors with file, line and the allowed list.
- Navigation no longer intercepts a `method="dialog"` form (or a `formmethod="dialog"` button): it closes its dialog instead of being POSTed to the page's URL (a 405 on the showcase).
- Showcase: a deferred signup form page (`/components/deferred-form/`) with an e2e check of the deferred save, and a `brick:confirm` "Delete all" on the ConfirmDialog page with an e2e check of the kit confirmer.

#### Validation (v7 batch B)

- Declared rules: `brick: {rules: {email: [required, email, {max: 120}]}}` and `brick: {messages: {confirm.same: "…"}}` on a stateful component. The default validator (package `validate`, stdlib only) has `required`, `min`, `max`, `email`, `url`, `pattern`, `in` and `same`, with English messages. An unknown rule, a bad argument, a path not in `state:` and a message naming no rule are compile errors with file and line.
- Touched fields: an instance keeps `Touched` (sealed and encoded with it, `"touched"` in the JSON v1 shape, omitted when empty). `$set` and `sets` touch the paths they send. Every render computes `.Errors` (rule errors for touched fields, overlaid by the action's own `[state, errors]`, which win) and a new `.Touched` map.
- Starlark: `brick.validate(fields = None)` touches and checks fields and returns path → message; `brick.untouch(fields = None)` clears them. Both reach the engine through `brick.ValidationFrom(ctx)`. Nothing validates an action automatically.
- `Options.Validator` (`brick.Validator`, `brick.Rule`) replaces the default: go-playground, ozzo, CUE or a localising wrapper; it receives the render locale.
- Showcase: a validated signup form (`/components/validated-form/`) with an e2e check of the blur error and the submit.

#### File uploads (v7 batch C)

- `brick: {uploads: {avatar: {accept: [image/png], max_size: 2MB, max_files: 1}}}` names the state fields that take files: `null` for one file, `[]` for several. Compile errors for an undeclared or non-null/non-list field, `max_files` above 1 on a one-file field, a bad size or media type, an unknown key, and `uploads:` with no sink configured.
- The `UploadSink` seam (`Options.Uploads`): `Open(ctx, UploadMeta)` returns an `UploadWriter` (`Write`, `Close() → UploadRef`, `Abort(err)`), with the optional upgrades `UploadRemover` and `UploadPresigner` detected by type assertion. Scripts only ever see the ref dict (`id`, `name`, `type`, `size`, `url`, `meta`); keeping a file is a host capability.
- `/_brick/upload` (`Engine.UploadHandler`, served by the site layer under any base path): one PUT per file, run through `ActionMiddleware` as the pseudo-action `$upload`, so auth, quotas and rate limits apply unchanged. The size is counted while streaming (413), the type is sniffed from the first 512 bytes and checked against `accept` (415), and every failure aborts the writer. The ref is set or appended, the field is touched and validated, and the answer is the normal action envelope. `Engine.RunUpload` runs the same pipeline without HTTP.
- Presigned uploads: with an `UploadPresigner` sink the runtime asks for a target, PUTs straight to storage, then calls `$uploaded(field, id)`; the engine accepts only an id it issued to that instance and field within the hour (kept in the sealed instance as `"pending"`), and re-checks the limits on what `Confirm` reads from storage.
- `$removeUpload(field, id)` deletes through `UploadRemover` and is refused when the sink cannot remove. `$set` and `sets` cannot write an upload field.
- Runtime: `brick:upload="field"` on `<input type="file">`, `brick.upload(el, field, files)` for drops and pastes, XHR with progress on `<progress brick:upload-progress="field">`, `data-uploading` on the input, `upload-progress` / `upload-done` / `upload-error` on `brick.on` (`gone` on a 410, which is never replayed; `cancelled` for the client-only `$cancelUpload(field)`), advisory checks from the engine-written `data-brick-uploads`, and uploads queued in order with the component's other actions.
- `upload/disk`: the reference sink (stdlib only) with random ids, a TTL `Sweep`, `OpenFile` for the host to keep a file, and a `Handler` that serves files with `nosniff` (images inline, everything else as a download). `bricktest.MemoryUploads` and `LiveRoot.Upload` for theme tests.
- `contrib/upload-s3`: an S3 `UploadSink` that also implements `UploadRemover` and `UploadPresigner`. Proxied uploads stream into the bucket, holding at most one 5 MiB part in memory. Presigned PUTs sign the content type, the name and the declared length. `Confirm` reads the real size and type with `HeadObject`. The host passes in the `*s3.Client`, and orphans expire through a lifecycle rule on the temp prefix.
- The kit `Dropzone` passes `brick:upload` to its input and leaves the file list to the component. Showcase: an avatar upload (`/components/upload/`) through the disk sink, with an e2e check in headless Chrome.
- The site layer now rebases the HTML inside the action envelope under `BasePath` too, as it did for plain HTML answers.

#### The browser runtime (v8 batch A)

- Morph keys and controls: `brick:key` (a sibling-scoped key; `id` still wins; a duplicate warns once), `brick:ignore` / `brick:ignore.self` (keep an element, or only its attributes) and `brick:replace` (swap it for a fresh copy, remounting its client code), in any file. `brick:ignore` on a stateful root is a compile error, and a `{{ range .State.… }}` whose rows are plain elements without `id` or `brick:key` gets a Dev warning (code `unkeyed`).
- `brick:transition[="types"]` on a stateful root wraps its action morphs in a view transition; never for polls, `$set` or a recovery, and not under reduced motion, without the API, or while another transition runs.
- `brick:intersect="call"` (`.leave`, `.once`, `.half`, `.full`, `.margin.<n>px`), a new grammar row with the new `<px>` token: runs an action when an element enters or leaves the viewport, ignores reports while its own action is in flight, and re-arms after every morph.
- `brick.hook(name, fn)`: `request` (add headers or `cancel()`, on actions and upload XHRs; `Content-Type`, `Accept` and `Brick-*` are protected), `response`, `morph` (return `false` to leave an element as it is; a refused stateful root still takes its new handle), `morphed` and `ready`. The `action-cancelled` event. `brick.watch(el, path, fn)` follows a signal.
- `.optimistic` on `brick:click`, `brick:change` and `brick:keydown`, valid only with a literal `$set` or `$toggle` call (a compile error otherwise): the signal is written before the request and put back when the action fails.
- Navigation polish: `brick:current[.exact]` (`aria-current="page"` and `data-current` on the link to the page shown, segment-prefix by default), `html[data-navigating]` after 150 ms, a cancellable `navigate` event (`detail.preventDefault()`; a cancelled Back restores the address bar), scroll restore on back and forward, prefetch on focus and press, and `brick.navigate(url, {replace})` / `brick:nav="replace"`.
- `brick:ref="name"` with `brick.ref(el, name)` (a duplicate literal name in a file is a compile error), `brick:offline[.remove]` with `html[data-offline]`, and `brick:submit.lock` (text fields read-only, choices `aria-disabled`, while the form's action is queued or in flight).
- `brick new component <Name> [-state] [-client] [-island]` and `brick new page <path>` write starter files and never overwrite.
- Stateful components and islands take children and `<brick:prop>` blocks: the caller's content is rendered once at the call site and stored with the instance (`Instance.Slots`, sealed and size-capped with the state), so it survives every action. A `{{ node }}` given a value, `.Children`/`{{ child }}`, or an island or stateful component inside such a slot is a compile error. Fixes `<brick:render>` silently dropping a stateful component's children.
- Showcase: a "Live interactivity" page (`/interactivity/`) with an infinite, keyed, animated feed and an optimistic like button, checked by `task ui:e2e`.

#### Server state (v8 batch B)

- Renderless actions and replies: `brick.skip_render()` / `EffectsFrom(ctx).SkipRender()` stores the state and bumps the version without a render, and the envelope omits `html` and carries the root's new `handle` (and `token`), because a sealed store's handle changes on every save. `brick.reply(value)` / `EffectsFrom(ctx).Reply(v)` attaches a JSON value (counted in `MaxEffectBytes`); `ActionResult.Reply` and `.SkipRender` let middleware read or clear them, a failed action drops both, and `brick.action()` resolves with the reply. Dev warns when a renderless action changes state the template reads, or returns errors.
- `brick: {init: fn}` runs `fn(state, props)` once when an instance is created, before its first save, with the effects collector hidden; `brick: {updated: fn}` runs `fn(state, props, paths)` after `$set`, deferred sets, `$toggle` and `$reset` change fields (never after a named action), and its errors join `.Errors`. `$reset(path…)` puts fields back to their declared `state:` values and untouches them. Unknown functions are compile errors at the key's line.
- `brick: {query:}` syncs top-level scalar or list fields with URL parameters (`as`, `history: replace|push`, `keep`): `WithQuery(url.Values)` seeds a new instance through the `$set` gate (a bad value is ignored with a Dev warning, never failing the page), a changed field produces the new `query` effect (`{set, del}`, defaults dropped unless `keep`), the root carries `data-brick-query`, and Back/Forward that changes only owned parameters restores in place with `$refresh` and `sets`. Two components claiming one parameter warn in Dev; a dict field is a compile error.
- `brick: {remember: [field…]}` keeps fields per session through the new `Rememberer` interface (`Options.Remember`, `RememberKey`, `NewMemoryRemember`): loaded after `init` and before the URL, saved after an action that changed one (a `Save` error is reported, never failing the action), never without a session, and a compile error without a configured `Rememberer`. `Instance.Key` keeps the call's `key=`, which scopes a remembered set across pages.
- Dynamic route segments: `content/posts/[slug].html`, `[...rest]` and `[[...rest]]` route by pattern. A static page always wins; patterns are ordered segment by segment, and two with the same shape are an error. The page reads `.Page.Route` / `.Page.RouteParts`, and its loader reads `page.route`. `brick.not_found()` (Go: `brick.ErrNotFound`) answers with the 404 page and is never cached. `brick: {paths: ns.fn}` lists the values for `brick build` and closes the world in serve. `Site.Patterns()` and `brick routes` list the patterns. Route values are single URL segments: `.`, `..`, slashes, encoded slashes and control characters never reach a page. A stateful component keeps its page's route values in its instance (`Instance.Route`, `RouteParts`), so `.Page.Route` survives its actions.
- Showcase: a filter whose search and page live in the URL on `/interactivity/` (`init:`, `updated:`, `$reset`, `query:`), checked by `task ui:e2e` including Back.

#### Lazy islands and streamed replies (v8 batch C)

- Lazy islands: `brick:lazy` (`load`), `brick:lazy="visible"` and `brick:lazy="idle"` on a component call, or `brick: {lazy:}` as a component's default. The page holds `<brick-lazy data-brick-lazy="TICKET" data-when="…">` with the enclosing boundary's `loading` block (which no longer warns), and the runtime redeems the ticket at `GET {AssetBase}island?t=` (`Engine.IslandHandler`, mounted by `site` beside the action endpoint, rebased under `BasePath`), appends the answer's missing assets and swaps it in; a lazy answer may hold further lazy islands. Tickets go through the new `IslandTickets` seam (`Options.IslandTickets`, `NewIslandTickets`): by default sealed with the state store's sealer (`site`: `StateKeys`), otherwise kept in a bounded per-site memory store with a Dev warning; bound to the session, expiring after `DefaultIslandTicketTTL`, and kept apart from action handles. A forged, foreign, expired or unknown ticket answers 410 and the runtime reloads once. The island renders with the page's route, the page's query (`Brick-Query`) and `Options.ActionRequest`; a failure answers the boundary's fallback (Prod) or the error block (Dev) with `Brick-Island-Error: 1`. `Result.HasLazy` marks such a page private in `site`; export and an action's re-render show lazy islands in place. `brick:lazy="stream"` (section 15) shipped in v20, below.
- Streaming action output: `brick.stream(ref, text, replace = False)` in Starlark and `StreamFrom(ctx).Write` in Go (`ActionStream`, `WithActionStream`, `StreamContentType`). When the client accepts it and the action streams, the action endpoint answers NDJSON chunk lines, flushed as written, then the envelope or an error line; a middleware may wrap the stream before `next`. The runtime appends each chunk to the root's `brick:ref` as text and then lands the envelope; `bricktest`'s `LiveRoot.Stream` returns the chunks.
- Showcase: a slow panel loaded when it scrolls into view and "Brickbot streams its reply" on `/interactivity/`, with a demo-only `pause` script global, checked by `task ui:e2e`.

#### State stores in Redis and SQL

- `contrib/states-redis`: a `brick.BytesStore` on go-redis v9 for `brick.Bytes`, so state survives a restart and is shared across servers. Each instance is a hash at `<prefix>brick:st:<handle>` with `PEXPIRE` = TTL, refreshed on every read; a set per session (`<prefix>brick:sess:<session>`) makes it a `Revoker`, which deletes only instances still bound to that session; `SCAN` (on every master or shard) makes it a `BytesLister`. Every Redis failure is an error, never a miss, so an outage answers 503, not 410. No command touches two keys, so it runs on Redis Cluster. The host passes in the client; `task test:redis` runs the `statetest` suite against the shared local Redis.
- `contrib/states-sql`: a `brick.BytesStore` on `database/sql` (Postgres, MySQL, SQLite, or your own `Dialect`), with `Migrate`, per-row expiry, `RevokeSession`, listing and `Prune`; a database outage answers 503, never 410. Wrap it with `brick.Bytes`.

#### Action telemetry

- `contrib/actions-otel`: an OpenTelemetry `ActionMiddleware` (`otelactions.Middleware`). It opens one span per action (`<Component>.<action>`, uploads as `$upload`) with component, path, action, store, status, renderless and streamed-chunk attributes, and records an action duration histogram and a count by status. The host passes its own TracerProvider and MeterProvider, and the module never touches the globals. State, arguments, handles, tokens and session ids are never recorded, which a test pins. Refused action names collapse to `_unknown` so clients cannot inflate metric series.
- `brick.ActionStatus(err)` is the default status for an action error, the one the engine's error envelope answers with, so middleware that reports outcomes agrees with the client; `otelactions.Status` uses it.

#### Runtime retry and the brick-config meta

- The runtime sends an action again after a 503 (state store or limiter down) or a 429 (rate limit), waiting for the answer's `Retry-After` in seconds or as an HTTP date (1 s without one). It retries once by default, then fires `action-error`; a `Retry-After` longer than the cap (5 s) is reported at once instead of freezing the component. The job keeps its place in the root's queue with `data-loading` on, so order and the handle chain hold. Each retry carries `Brick-Retry: <n>`, fires `action-retry` (`{id, action, status, retry, wait}`), and runs the request hooks again with `retry` set, so a hook can cancel it. A 410 still recovers in place and is never retried; a started stream and an upload's bytes are never sent again.
- `Options.Runtime` (`RuntimeConfig`: `Debounce`, `PollMin`, `ActionURL`, `Retries`, `RetryMaxWait`, with `DefaultDebounce`, `DefaultPollMin`, `MinPollMin`, `DefaultRetries`, `NoRetry`, `DefaultRetryMaxWait`) tunes the runtime from Go. The fields that are set are written as `<meta name="brick-config">` just before the runtime script; the zero value writes nothing. `New` refuses a negative duration, a poll floor under 250 ms and an action URL whose path does not end in `/action`. With `ActionURL` set, actions, uploads and lazy islands go to that server with credentials `include`, so it must allow CORS with credentials.

#### v9: runtime and effects

- Row streams: an action edits a `brick:ref` list's rows without keeping them in state. `brick.rows(ref, op="insert"|"delete"|"reset", component=…, items=[…], key="id", at="top"|"bottom", limit=N, keys=[…])` in Starlark, `Effects.Rows(ctx, brick.RowsSpec{…})` in Go. Rows are always a component's render, matched by `brick:key`, and `limit` trims the opposite end.
- `brick.submit(form)` / `Effects.Submit(ref)`: after the morph, the browser natively submits a `brick:ref` form, for handing off to a classic POST such as a login that sets a cookie. It is terminal, like a redirect.
- `brick.reloadComponent(el)` re-renders a component fresh from the server, for recovering from an action that failed with a 500. `action-error` now carries `root`, `id` and `status`.
- `brick.debug(on)` logs every action request and answer to the console, and `brick.latency(ms)` delays each request. Both are off by default and are for local debugging.

#### v9: declarations

- Declared slots: `brick: {slots: {title: {required: true}}}` lists the blocks a component takes (`children` is the body); a call that leaves out a required block or passes one the component did not declare now fails at compile with the caller's file and line. Components that declare no slots are unchanged.
- Component docs: props and slots accept `doc:` and `examples:`, and `Engine.ComponentDocs()` returns every callable component with its props (type, default, required, oneof, doc, examples) and slots, for a docs page or `brick docs`.
- Temporary state: `brick: {temporary: [rows]}` renders a field with the value an action gave it, then saves the instance with that field back at its declared value, so large transient data (streamed rows, search results) never reaches the state store.

#### v9: diagnostics and built-ins

- `brick check` warns about unbalanced HTML (`html-balance`): an element that is never closed, a close tag with nothing to close, or a close tag that skips an open element, each with file and line. It follows every `{{ if }}`/`{{ else }}` branch separately, checks `{{ range }}` and component bodies on their own, knows void and optional-close elements, and warns only when every way the template can run is wrong. It never fails a check and never changes output.
- In Dev mode, the root element of every single-root component carries `data-brick-loc="components/Card.html:5"`, the file and line that wrote it, so the browser inspector leads straight to the source. Production output is byte-for-byte unchanged.
- `tag` and `endtag` built-ins write an element whose name is data, such as a heading level: `{{ tag (print "h" .Props.level) "class" "title" }}…{{ endtag (print "h" .Props.level) }}`. They write only elements without URL, script or raw-text content, refuse event-handler, URL and style attributes, and escape every value.
- A frontmatter error under a `brick:` key (for example `brick: temporary:` without `state:`) now points at that key's line instead of line 1.

#### v9: testing

- bricktest: `LiveRoot.State()`, `View()`, `AssertSet(t, path, want)`, `AssertErrors(t, paths...)` and `AssertNoErrors(t)` assert on the component's state and validation errors instead of its HTML.

#### v9: dev experience

- Dev instance inspector: with `site.Options.Dev` on, `/_brick/instances` lists the live stateful instances of every state store that can list them (`brick.Lister`): component, file, page, age, approximate size, version and a short session hash. #### v9: loaders

- Batch loaders: a component can name `brick: {load_many: mod.fn}` instead of `load:`. Its calls wait until the page or island has run, then the loader is called once per nesting level with a list of every distinct `{props, page, ctx}` input and returns a list of dicts in the same order, so `{{ range .Users }}<UserCard id=.ID>` costs one data call instead of N. Output and instance ids match an unbatched render. Inside a `<brick:boundary>`, a slot or an island's own root, the call is answered at once by a one-element batch.

#### v12: checking a site whose host supplies capabilities

#### v12: shared rate limits

#### v13: locked state fields and page translations

- Locked state fields: `brick: {locked: [editing_id]}` makes a stateful component's field writable only by the server (actions, `init:`, `updated:`, remembered values). A client `$set`, `$toggle`, `$reset`, deferred set (`brick:model.defer`) or `brick:model` on a locked field, or on any path below it (`draft.title` when `draft` is locked), is refused with a 422 naming the field (`brick.ErrLockedField`, which is an `ErrBadValue`); nothing is applied and the action does not run. `brick check` fails a `brick:model` bound to a locked field, a literal `$set`/`$toggle`/`$reset` naming one, a `locked:` entry that is not a top-level `state:` field, and a field that is both locked and in `query:` or `uploads:` (both are written by the client). Opt-in: without `locked:` nothing changes.
- `.Page.Translations` lists the same page in the site's other locales (`{Locale, URL}`, in `site.Options.Locales` order, never the page itself), and `.Page.URL` is the URL being rendered, so a layout can write `<link rel="alternate" hreflang>` tags and a language switcher. The site layer pairs a shared page's per-locale routes, variant-only files of one stem (`team.fr.html`, `team.de.html`, each keeping its own `brick: {url:}`), and dynamic pages (the matched values carry over). A page in one language gets an empty list. A Go host with its own router passes `brick.WithURL(u)` and `brick.WithTranslations(ts)`. The kit's `NavigationMenu` and `AppShell` examples, which already wrote `current="{{ .Page.URL }}"`, now work under the site layer.

#### v13: editors and tests

- `editors/vscode` highlights brick markup in `.html` files with a TextMate injection into VS Code's HTML grammar: `{{ … }}` actions (keywords, `$variables`, `.Fields`, strings, pipes) anywhere, including attribute values; component tags (`<Card>`, `<ui.Card>`, `<x-card>`) and engine tags (`<brick:prop>`); and `brick:*` attributes in any tag. It works without the language server. `task vscode:test` tokenizes sample markup through the grammar.

#### v14: more events and key combos

- `brick:input`, `brick:focus`, `brick:blur` and `brick:keyup` event attributes. `brick:input` runs on every edit with the control's value (pair it with `.debounce.300ms`) and waits out an IME composition; `brick:blur` passes the control's value like `brick:change`; `brick:focus` passes none. Focus and blur use only the element's own attribute, never an ancestor's. `brick:keyup` takes the same keys and modifiers as `brick:keydown`, including `.window`, and never prevents the key's default.
- Key combos on `brick:keydown` and `brick:keyup`: `.ctrl`, `.meta`, `.shift`, `.alt` before a key (`brick:keydown.ctrl.enter`, `brick:keydown.meta.k`). A keyed attribute matches only when exactly its modifier keys are held. The keys now include the letters `a`-`z` and digits `0`-`9`, matched by `e.key` or by the physical key (`e.code`), so `alt+k` on a Mac still matches `.alt.k`. A modifier without a key (`brick:keydown.ctrl`) is a compile error.
- `brick:click.outside`: the call runs for a click that lands outside the element, not while the element is hidden (`[hidden]` on it or an ancestor, or `display:none`), and never prevents the click's default. A plain `brick:click` on the same element still runs for clicks inside.
- `bricktest` drivers `Input`, `Focus`, `Blur`, `Keyup`, `LivePage.Keyup` and `ClickOutside`; `Keydown`/`Keyup` accept combos written `"ctrl+Enter"`, `"meta+k"`.

#### v14: output pages, the sitemap and page headings

- **Output pages.** A page file with a second extension before `.html` renders that file at its exact name: `content/feed.xml.html` serves and exports `/feed.xml`, `content/robots.txt.html` serves and exports `/robots.txt`. Allowed formats are `xml`, `rss`, `atom` and `txt`, served as `application/xml`, `application/rss+xml`, `application/atom+xml` and `text/plain` (all `; charset=utf-8`). An output page gets no layout unless its frontmatter names one, and nothing HTML is added to it (no Dev toolbar, live reload, `<base>`, URL rewrite or speculation rules). A leading `<?xml …?>` prolog is written as is. Output pages are not in `.Site.Pages`, so a feed that ranges over it never lists itself. `Route.Output` and `Page.Output` name the format (`brick routes -json` shows it).
- **Refused formats.** `data.json.html`, `.js`, `.mjs`, `.css` and `.csv` output pages stop the site with a `site.CodeOutput` error that says why: html/template escapes for HTML, so a quote becomes `&#34;` and JSON breaks. A markdown output page (`feed.xml.md`) and an output page with a `[param]` segment are refused the same way. Any other second extension (`v1.2.html`) is an ordinary page, as before.
- **Built-in sitemap.** `brick.yaml` `sitemap: {}` (or `site.Options.Sitemap`) serves `/sitemap.xml` and writes it in `brick build`. Locations are absolute, from `sitemap: {baseURL: …}` or else `baseURL` in `site.yaml`, plus `-base`/`BasePath`. A translated page lists its `hreflang` alternates, itself included, from the same pairing as `.Page.Translations`. Left out: drafts (even in `serve`), output pages, the 404 page, dynamic pages without `brick: {paths:}`, and any page with `brick: {sitemap: false}`. A project's own `content/sitemap.xml.html` or `static/sitemap.xml` wins over the built-in one. `brick build` prints `wrote public/sitemap.xml` and `-json` has `"sitemap": true`.
- **`.Page.Headings`.** A markdown page's layout can read its headings (`Level`, `ID`, `Text`) to build a table of contents, when the site's Markdown backend implements `brick.MarkdownHeadings` (contrib/markdown-goldmark does). With a backend that does not, the list is empty. New root API: `brick.Heading`, `Page.Headings`, `brick.WithHeadings`.
- **`brick.yaml` `markdown:`** (read by the brick CLI only, like `tailwind:` and `sitemap:`): `markdown: {headingIDs: true, highlight: true}`. `headingIDs` writes an id on every markdown heading (`<h2 id="install-brick">`), so `.Page.Headings` tables of contents can link; `highlight` highlights fenced code with CSS classes. Both are off by default, so `.md` output is unchanged without the section. A Go host sets the same through `markdowngoldmark.New(markdowngoldmark.WithHeadingIDs(), markdowngoldmark.WithHighlight())`; the Go type is `brick.MarkdownConfig` (`Config.Markdown`), which `Config.Apply` ignores.
- New frontmatter key: `brick: {sitemap: false}` (rule A13: under `brick:`). It is in `brick schema` output and the unknown-`brick:`-key warning list.

#### v14: markdown heading ids and highlighting

- `contrib/markdown-goldmark`: `New` takes options, all off by default, so `New()` writes the same bytes as before. `WithHeadingIDs()` gives every heading a deterministic slug id, deduplicated within a document (`intro`, `intro-1`, ...). `WithHighlight()` highlights fenced code with chroma using CSS classes, never inline styles; `WriteHighlightCSS(w, style)` writes the stylesheet for a named chroma style. `Slug(text)` is exported. #### v15: loader answers — redirects, error statuses and headers

- **Loader answers.** A loader can now say more than "not found". Starlark: `brick.redirect(url, status=303)` (302, 303, 307 or 308), `brick.error(status, message="")` (any 4xx or 5xx) and `brick.header(name, value)` (only `Cache-Control`, `Content-Language`, `Expires`, `Last-Modified`, `Link`, `Vary`, `X-Robots-Tag`). Go: the typed answers `*brick.Redirect` and `*brick.HTTPError` beside `brick.ErrNotFound`, made with `brick.NewRedirect` / `brick.NewHTTPError`, recognised with `brick.IsAnswer`, and `brick.SetHeader(ctx, name, value)` for a Go script backend.
- **Protected pages.** Put the guard in an island's loader (`brick: {island: true}`, `inject: {user: …}`): the site layer runs it per request through `Engine.Fill`, so a signed-out visitor gets `303 Location: /login/`, a signed-in non-admin gets `403` through the error page, and both answers carry `Cache-Control: private, no-store`. The cached page never holds one visitor's answer for another.
- **`content/error.html`** (or `.md`): the page the site renders for `brick.error`, with the answer in `.Ctx.error.status` and `.Ctx.error.message`. Like `404.html` it is not a page of the site. Without one, the status is sent as plain text (the message, else the status text). New `Site.RenderError`.
- **`Engine.RedirectLocation(r, rd)`**: the open-redirect lock for a loader's redirect. A path on this site always passes; an absolute URL only on the request's own host or one of `brick.Options.RedirectHosts` (the existing typed opt-in that action redirects already use). A refused target is a 500, logged, never followed.
- **`Result.Headers`** carries the page and layout loaders' headers (cached with the page, sent on every response); `brick.WithResponseHeaders(ctx, h)` collects an island's headers on `Fill`.
- **`brick build`**: a page whose loader (or an island's loader) redirects is written as a meta-refresh page to the target, with `rel=canonical` and `noindex`, and nothing of the page itself; a loader's error status stops the build with `site: export /posts/gone/: its loader answered 410, which a static file cannot send`. Loader headers are dropped (the static host sets its own).

#### v15: impressions and background polls

- `brick:intersect.dwell[.<n>ms]` runs its call only after the element has stayed in view for that long without a break (1000 ms when no duration is given, `brick.DwellDefaultMS`), for impression tracking. Leaving the viewport or hiding the tab cancels the wait, and the next stay starts it from zero. It fires once per stay, so a row read for a minute counts once; it combines with `.once`, `.half`, `.full` and `.margin.<px>`. `brick check` refuses it on any other attribute, with `.leave`, given twice, or with a malformed duration (`.dwell.2s`: durations are `<n>ms`).
- `brick:poll.keep-alive` keeps a poll running while the tab is hidden; every other poll skips its ticks in a background tab, as before. With `.visible` as well, the element must still be in view as last reported. `brick check` refuses `.keep-alive` on any attribute but `brick:poll`.
- `bricktest`: `LiveRoot.IntersectFor(selector, d)` drives a stay of length `d` (the element enters, stays `d`, then leaves), so a `.dwell` longer than `d` does not run; `Intersect` is a stay long enough for any `.dwell`, and `Leave` ends the stay.

#### v15: references and rename in the language server

- `brick lsp` answers **find references** and **rename**. References on a component tag (`<Card>` or `<x-card>`, open or close), or anywhere in the component's own file, list every call across the site's pages, layouts and components, in both tag forms and through `use:` aliases; on a prop inside a component tag they list every place that prop is passed (attributes and `<brick:prop name="…">` blocks), plus its declaration. Rename (with prepareRename) renames a component everywhere: each tag keeps its form (`<x-card>` becomes `<x-tile>`), `use:` paths that name its file are rewritten, and the file and its locale variants are renamed in the same edit through RenameFile operations. It is refused, with the reason, for a kit or vendored-library component, a name that is not a component name, a taken name, and an editor that cannot rename files in an edit. Both scan with the engine's own lexer, so a tag-shaped string in `{{ }}`, a comment, a raw body or a `<brick:script>` is never a reference and never renamed.

#### v16: forms that work without JavaScript

- Forms work with JavaScript off (progressive enhancement for `brick:submit`): a stateful component's `<form brick:submit="save">` is rendered with `method="post"`, hidden `brick:state`, `brick:token`, `brick:action` and `brick:models` fields and a `name` on every `brick:model` control, so without the runtime it posts to its own page as an ordinary form. The site runs the action through the same pipeline as a JSON action (token, session, locked fields, middleware, rules), then answers `303` back to the page (the new state rides a 60-second `HttpOnly` cookie, `__Host-brick-form` on HTTPS, consumed by that page) or, when the action returned errors, the page itself with `422`, errors and typed values shown. A `brick.redirect` or `brick.navigate` effect becomes the `303` target; other effects are dropped. With JavaScript on nothing changes: the runtime drops every `brick:` field from the dict it sends.
- Left inert on purpose: a form that writes its own `action` or `method`, a form with `brick:confirm`, and client-only calls (`$dispatch`, `$parent.fn`, `$cancelUpload`). A file chosen with scripts off is not stored.
- `Engine.IsFormPost`, `Engine.FormPost`, `Engine.SetFormResume`, `Engine.FormResumeOption`, `Engine.FormError`, `brick.WithFormResume` and `FormPostResult` / `FormResume`, for a host with its own router; `Options.NoFormPosts` turns the fallback off.
- Form posts are refused unless `Sec-Fetch-Site` is `same-origin`, or, when a browser does not send it, `Origin` names the request's host (`403`).

#### v16: image formats and WebP

- `{{ image }}` takes an output format after its widths, `{{ image "~/static/p.png" 480 960 "webp" }}`: `"jpeg"` and `"png"` are built in, and `Options.ImageEncoders` (`brick.ImageEncoder`: `Format()` and `Encode(w, img)`) adds others. A format nobody registered is an error naming it and the formats that exist, never a silent fallback; a registered `"png"` or `"jpeg"` replaces the built-in one. Widths from JSON data (whole floats) are accepted.
- `contrib/image-webp`: lossless WebP through nativewebp (pure Go, no cgo), with one option, `WithCompression` (0–6, size and speed only, never pixels). Output files end in `.webp` and are served as `image/webp`. The `brick` CLI registers it for every site, so `brick build` and `brick serve` need no configuration; a site that never names `"webp"` renders byte-identical.

#### v17: KMS key providers

- `contrib/keys-awskms`, `contrib/keys-vault`, `contrib/keys-gcpkms`: `brick.KeyRing` providers that keep the state keys in AWS KMS, Vault's transit engine or Google Cloud KMS instead of a plain `BRICK_SECRET`. All three use envelope encryption: each 32-byte data key is stored encrypted (the ciphertext is not a secret and can live in config or an environment variable), `New` asks the KMS to decrypt every one once at start and returns an ordinary `StaticKeys` ring, so sealing stays local and no request waits on or pays for a KMS call. The first wrapped key seals and every one opens, so rotation works as with `BRICK_SECRET=new,old`. Any failure at start (no key, a KMS error, the wrong key, context or AAD, a key of the wrong size) is an error and no ring; nothing falls back to running without a key, and errors never carry key bytes. KMS plaintexts are zeroed once the ring holds its copies. `NewWrappedKey` makes a data key in wrapped form (AWS `GenerateDataKey`, Vault `datakey/wrapped`, Cloud KMS `Encrypt` of a local random key with CRC32C checks). AWS pins `KeyID` and supports an encryption context; Vault takes the host's authenticated `*api.Client` (any auth method) and supports derived keys; GCP verifies CRC32C on every request and response. `task test:keys` runs the AWS module against a throwaway LocalStack KMS and the Vault module against a throwaway `vault server -dev`, both from the new `compose.yml` and removed after the run. The GCP module has no emulator to test against: it is tested against an in-process fake only and has not been run against real Cloud KMS. It needs Go 1.26 (the current `cloud.google.com/go/kms` does).

#### v17: server push

- A stateful component refreshes when a topic it listens to is published: `brick: {listen: orders}`, a list, or `{topics: [...], keep_alive: true}`. A topic may use `{{ .Props.x }}`, `{{ .State.x }}`, `{{ .Params.x }}` and `{{ .Key }}`; it is 1–200 characters from `A-Z a-z 0-9 _ . : / @ -` (`brick.ValidTopic`), checked at compile when literal and at render when templated. `listen:` needs `state:` and `Options.Push`, or the file fails to compile.
- Publishing: `brick.publish("orders")` in a Starlark action and `Effects.Publish` in Go publish once the action succeeded and its state is saved (a failed action publishes nothing; a topic named twice is published once); `Engine.Publish(ctx, topic)` publishes from any Go code.
- `Options.Push` (`brick.NewPush(brick.PushOptions{})`) and the `brick.Broadcaster` seam (`Publish`, `Subscribe`), with `brick.NewMemoryBroadcaster` for one process. `PushOptions` sets the `Sealer` for listen tokens (a per-process key by default), `TokenTTL` (24 h), `MaxConnections` (1 000; 503 with `Retry-After` beyond), `MaxTopics` (64 per stream), `Heartbeat` (25 s), `Retry` (2 s) and `AuthorizeTopic`.
- `Engine.EventsHandler` serves `GET /_brick/events?l=TOKEN…` as `text/event-stream` (the site layer mounts it). Subscribing is closed by default: each listening root carries the topics and a listen token sealed for them, the session and an expiry, and the stream subscribes only to the topics inside tokens that open; a forged or foreign-session token is 403, an expired one 410, a topic `AuthorizeTopic` refuses 403. Events carry the topic only, never data. A stream ends, and its subscription with it, when the client leaves.
- The runtime opens one `EventSource` per page for every listening root, reopens it only when the page's set of topics changes, refreshes each listening root at most once per tick, defers refreshes while the tab is hidden (except `keep_alive`), refreshes every listener once after a reconnect, retries a refused stream with backoff (1 s doubling to 30 s, 8 times, then a `push-error` event), and closes the stream on `pagehide`.
- `contrib/push-redis`: a `Broadcaster` on Redis pub/sub with one pattern subscription per process, fanned out locally; tested live by `task test:redis`. The `brick` CLI enables in-memory push for every site, and the showcase's interactivity page has a live board that updates in every open window.

#### v18: client commands, exit transitions and prompted actions

- **Client commands, `brick:js.<event>`**: a fixed list of DOM commands that runs in the browser with no request, on any page: `show`, `hide`, `toggle` (the `hidden` attribute), `addClass`, `removeClass`, `toggleClass`, `setAttr`, `removeAttr`, `toggleAttr(t, name[, on[, off]])`, `focus` and `dispatch(t, name[, detail])`. Commands are separated by `;` and every argument is a JSON literal: `brick:js.click='toggle("#menu"); toggleAttr("this", "aria-expanded", "true", "false")'`. The target is a CSS selector (every match), `"@name"` (a `brick:ref` in the element's own scope), `"this"`, or `"closest <selector>"`. Events: `click dblclick input change submit focus blur keydown keyup mouseenter mouseleave`, plus `.once`, `.outside` (click only), and `.window` and key combos (keydown and keyup only). What a command changes survives the next morph (sticky), so a menu it opened stays open when an action re-renders the component. The compiler checks the event, the modifiers and every literal command. `setAttr`/`toggleAttr` refuse event handlers (`on*`), `srcdoc`, engine attributes and script URLs; `dispatch` refuses brick's own event names. The runtime repeats these checks, because `{{ }}` can fill a value.
- **Exit transitions, `brick:leave="classes"`**: when a morph drops an element, a `rows` delete or `limit` trim removes it, or a JS `hide` hides it, the runtime first adds these classes. It waits for the transition or animation they start, then removes or hides the element. The wait is capped at 2 s and skipped under `prefers-reduced-motion`. While it plays, the element is `inert` and carries `data-brick-leaving`. A second morph never reuses it, and a `show` cancels a `hide` that is still playing. One attribute is enough for a CSS transition, as in `brick:leave="transition-opacity duration-300 opacity-0"`, because a transition takes its timing from the style after the change.
- **`brick:confirm.prompt="Question?"`**: asks the visitor for text before the action runs. The answer becomes the call's last argument, after the call's own arguments and any event value. Cancel sends nothing; an empty answer is still sent. `brick.promptWith(fn)` replaces `window.prompt` (fn returns the text, null for cancel, or a promise of either) and returns a restore function, like `brick.confirmWith`. bricktest has `ClickPrompt(selector, answer)`; `Click` refuses a `.prompt` element so a test cannot skip the answer. The no-JavaScript form fallback skips a form with `brick:confirm.prompt`, as it skips a plain `brick:confirm`.

#### v18: background jobs

- Background jobs: an action calls `brick.start_job(name, args = None, topic = None)` (Go: `Effects.StartJob`, `Engine.StartJob`), answers at once, and the job runs after the response; when it ends it publishes its topic, so every component listening to it (v17 push) refreshes and reads the result through its own render. Jobs are a closed set of Go functions (`brick.NewJobs(brick.JobsOptions{Funcs, Push, ...})`, `Options.Jobs`); a job starts only after the action succeeded and its state was saved, never sees the request's state, session or request, and runs under its own context (`JobsOptions.Timeout`, 10 minutes by default, cancelled by `Jobs.Close`). Args are JSON values up to 16 KiB (`MaxJobArgsBytes`). The default queue is an in-process pool (`Workers` 4, `QueueSize` 256; a full pool refuses with `ErrJobQueueFull` rather than stall the action); a site plugs a real queue in through `JobsOptions.Queue` (one method, `Enqueue`) and its worker calls `Jobs.Run`. Every failure (an error, a panic, the timeout, a refused queue, a job still waiting at `Close`, a failed publish) reaches `JobsOptions.OnError` (default `slog.Error`) before the topic is published, and a refused queue also reaches the engine's `OnError` hooks. Showcase: the interactivity page's "Background jobs" block (`demos/RuntimeJob.html`, `demodb/db_jobs.go`).

#### v18: scoped styles and closed-by-default state

- **Scoped styles can reach a nested component's root**: `<brick:style scoped="inclusive">` lets a component's scoped rules style the root element of a nested scoped component (to place or size it) but nothing inside it. It compiles to `@scope ([data-brick-s="…"]) to ([data-brick-s] > *)`. Bare `scoped` (or `scoped="exclusive"`) keeps the v1 output byte for byte. Any other value is a compile error at the block's line.
- **`Options.StyleTransform`**: a hook that receives each `<brick:style>` block (`brick.StyleBlock`: file, content hash, scoped, bound, source, and the CSS the engine would ship) and returns the CSS that ships instead, for a minifier, a fallback for browsers without `@scope`, or another scoping strategy. It runs at compile time and must be deterministic, because its output is content-hashed into the asset URL. An error fails the compile, naming the file and line.
- **Closed-by-default state** (opt-in): `Options.LockState` (brick.yaml `lockState: true`) closes every stateful component's state to the client. The browser may then write only the fields a component lists in `brick: {writable: [...]}`, plus its `uploads:` and `query:` fields, which the client writes by declaration. Per component, `brick: {lock_state: true|false}` overrides the engine setting, and `writable:` alone closes that component. A refused write answers 422 with `ErrLockedField` naming the field, exactly like `locked:`. A literal `brick:model`, `$set`, `$toggle` or `$reset` that targets a field the client may not write is a compile error that names the fix. Off by default, so existing sites are unchanged; `brick: {locked:}` keeps working and wins over `writable:` (listing a field in both is a compile error). `lock_state` and `writable` are in the frontmatter schema, so `brick lsp` completes and explains them.

#### v19: push streams end with what opened them

- **Security:** an open server-push stream (`/_brick/events`) is no longer trusted for longer than what opened it. It ends when its earliest listen token expires (`PushOptions.TokenTTL`): the server first sends one `refresh` per topic, so every listening component re-renders with fresh tokens, then closes, and the runtime's retry reopens with them. A recheck every `PushOptions.Recheck` (default `DefaultPushRecheck`, 1 minute; runs when `Options.Sessions` or `AuthorizeTopic` is set) ends it when the session changed, cannot be confirmed, or a topic is no longer authorized, and `Push.RevokeSession(ctx, session)` ends that session's streams at once on every server sharing the broadcaster. `Engine.RevokeSession` calls it too, so one sign-out call ends the session's state instances and its streams. Before, the token, the session and `AuthorizeTopic` were checked only when the stream opened.
- `ValidBroadcastTopic` reports whether a `Broadcaster` should carry a topic: a `ValidTopic` or one of the engine's own `brick:` control topics. `contrib/push-redis` carries revocations to every server under its prefix (no new connection).

#### v19: uploads in forms that work without JavaScript

- A `brick:submit` form holding an `<input type="file" brick:upload="field">` now uploads with scripts off: the rewrite adds `enctype="multipart/form-data"` and puts the instance fields first, and `Engine.FormPost` streams each file part through the `$upload` pseudo-action (the same `ActionMiddleware`, `uploads:` limits, sniffed type, `max_files`, `UploadSink` and rules as a runtime upload) before the form's action runs, then answers 303 or 422 as in v16. A refused file stops the post before the action and shows the 422 page with the refusal as the field's error (`.Errors.<field>`). File bytes never count against `MaxActionBytes` and are never spooled. Cross-site posts are refused before a byte reaches the sink. Showcase: the uploads page's no-JavaScript profile form (`demos/FormNoJSUpload.html`), checked with scripts disabled in headless Chrome.

#### v19: validation rules on list items

- Wildcard validation rules: a `*` segment in a `brick: {rules:}` path covers every element of a list (`todos.*.title: [required, {min: 2}]`), nested lists included (`todos.*.tags.*`). Errors are keyed by the concrete path (`todos.2.title`), `brick.validate()` expands wildcards against the submitted state, `brick.validate(["todos.*.title"])` and `brick.untouch(["todos.*.title"])` accept a pattern, and `messages:` overrides name the pattern (`todos.*.title.required`). `validate.Wildcard`, `validate.Match`, `validate.Expand` and `validate.Exists` are exported for host validators; a custom `Options.Validator` gets the pattern in `Check` and the concrete path in `Validate`.

#### v19: instance end hook

- **Instance end hook**: a `brick.InstanceEndHook` in `Options.Hooks` is told when a stateful component instance ends, with `InstanceEnd{Store, Reason, At, Instance}` (a copy of the last saved instance: `Name`, `Path`, `ID`, `Handle`, hashed `Session`, `State`, `Pending` uploads). It never carries a request. Reasons: `brick.EndExpired`, `brick.EndEvicted`, `brick.EndRevoked`.
- The optional store upgrade `brick.EndWatcher` (`WatchEnds(fn) []EndReason`) and its bytes-level twin `brick.BytesEndWatcher` (passed through by `brick.Bytes`): a store reports only the reasons it can see and says which. The engine logs the reasons a store will never report.
- `MemoryStates` reports expired (at lookup, eviction and the new `Prune`), evicted and revoked, and is now a `brick.Pruner`, so `site.Options.PruneEvery` sweeps expired in-memory instances too. `contrib/states-sql` reports expired (at `Prune`, row by row so two servers report each end once) and revoked. `contrib/states-redis` reports revoked only: Redis deletes an expired key itself. `SealedStates` reports nothing.

#### v19: prop rename in the language server

- `brick lsp` renames props: from the `props:` (or `brick: {slots:}`) key, a `.Props.x` use, a call-site attribute (`title` or `:title`) or a `<brick:prop name>` block, one rename edits the declaration, every use in the component and its locale variants (`.Props.x`, `$.Props.x`, `.Attrs.x`, `index .Props "x"`, `attrs "x"`, `node "x"`, `hasNode "x"`, `props["x"]` in its script), and every call site across the site. It refuses the whole rename, naming the sites, on a clash or where a site cannot be followed (`brick:spread`, `.Props` handed on whole, `load:`, a computed `props[k]`); uses it cannot tell are this prop are left alone and listed in a warning.
- Find references on a prop lists its declaration, its uses inside the component and every call site (including `:title=…`), from any of those positions.

#### v20: streamed islands

- **Streamed page render**. The page is sent at once with each stream island's boundary `loading` block, the islands render concurrently (at most `Options.StreamWorkers`, default `DefaultStreamWorkers` = 4), and each is written into the same response when it is ready, in completion order, then moved into place by a tiny inline script (with the page's nonce when `WithNonce` is given). New API: `Engine.FillStream(ctx, r, opts...) (page, *Fills, error)`, `Fills.Each(ctx, fn)`, `Fills.Len()`, `Fills.Failed()`, `Engine.Stream(ctx, w, flush, r, opts...)`, `Result.HasStream()`, the exported mode constant `brick.LazyStream`. The site layer streams only a browser document load (`Sec-Fetch-Mode: navigate`) on a writer that can flush, sets `X-Accel-Buffering: no`, rewrites the fills' URLs under `BasePath`, and logs each island that failed. Every other request (curl, crawlers, `nav.js` client navigation), `Engine.Fill` and the static export render a stream island in place, with the same bytes as a plain island.
- A stream island that fails never fails the page, whose status is already sent: Prod writes the boundary's `fallback`, Dev the error block and the fallback, and the error reaches `OnError` hooks and `Fills.Failed()`. A loader answer (redirect, status) inside a stream island shows the fallback and is not reported as a fault, as for lazy islands. A loader's `brick.header` in a stream island is dropped (the headers are gone), with a Dev warning. A `stream` island inside an island being filled (a lazy answer, an action's re-render excluded) loads as `load` instead: an answer cannot stream part of itself. When the runtime places a fill (a CSP blocked the inline script, or the fill brings new assets), `island-loaded` fires with `stream: true`.

#### v20: client errors, scroll keeping and Dropzone previews

- **`brick.errors(el)`**: client code reads the validation errors of el's stateful component as its last render left them, with no request: `has(path?)`, `get(path)`, `first(path?)`, `all()`, `clear(path?)` (fires the new reserved event `errors-cleared`). The server writes them on the stateful root as `data-brick-errors` (JSON, keys sorted), only when the render's `.Errors` is non-empty, so a root without errors keeps its bytes.
- **`brick:scroll="<name>"`** keeps a scroll container's position across brick navigation. A forward navigation carries the position to the next page's container of the same name; back and forward restore the position that history entry had; the dev server's live reload keeps it. The name is required and compile-checked (letters, digits, `-` and `_`, no modifiers, unique per file). Kit `Sidebar` gains `keepScroll="<name>"`, and the showcase's docs sidebar uses it (`brick:scroll="docs-nav"`).
- Kit `Dropzone`: a chosen image shows a thumbnail before it is sent, built from a `blob:` URL in the browser. The URL is revoked when the file leaves the list (removed, replaced, uploaded or refused) and on unmount. Other file types keep the file icon, and so does an image the browser cannot decode. With `brick:upload`, the list shows the files still uploading (images with their thumbnail) and drops each one when its upload ends; the component's own re-render after each upload no longer wipes the rows of files still in flight.

#### v20: struct-typed props

- A `map` prop can declare its shape with `fields:` (field name → a type or `{type, required, oneof, doc, examples, fields, of}`), and a `list` or `map` prop its elements with `of:`, nested to any depth: `author: {type: map, required: true, fields: {name: {type: string, required: true}, social: {type: map, fields: {github: string}}}}`, `posts: {type: list, of: {type: map, fields: {title: string, url: string}}}`. `brick check` (and anything built on `CompileAll`) then warns, with the new code `prop-shape`, when the component reads a field the shape does not list (`.Props.author.emial`, `.gihtub` inside `{{ with .Props.author.social }}`, `.tilte` inside `{{ range .Props.posts }}`, through `$variables`, `index` and component bodies), when a call site passes a `dict`/`list` literal with a misspelled field, a missing required field or a mistyped value, when a `.Data`/`.Params` value lacks a required field, when a caller passes its own shaped prop that lacks a required field, and when a shaped prop's `default:` does not fit. All of it is check-time only: rendering never reads a shape, so loader output and Go values are never checked and nothing about a render changes. `Schema.Validate` (content collections) checks nested `fields:`/`of:` too, allowing extra keys.

#### v20: site, logging and testing

- **Route metadata**: `site.Route` (what `Site.Routes()` and `Site.Patterns()` return, and `brick routes --json` prints) now carries `Dynamic` (a `[param]` pattern route), the page's `Title`, `Description`, `Date`, `Draft` and `Section`, and `Meta`, the page's frontmatter without `brick:` (what templates read as `.Params`). #### v21: runtime — window focus, loading targets, enter transitions, `brick.js`

- `brick:focus.window` and `brick:blur.window` run an action when the browser window (the tab) gains or loses focus, with no value, such as a refresh when the user comes back. `brick:js.focus.window` and `brick:js.blur.window` do the same for client commands. In tests, `bricktest.LivePage.WindowFocus()` and `WindowBlur()` fire them in document order; `LiveRoot.Focus` / `Blur` ignore `.window` attributes.
- `brick:loading` targets more than action names: a call with arguments, `brick:loading="remove({{ .id }})"`, lights only the row being removed (arguments match as a prefix, so a `.prompt` answer or an event value appended to the call still matches); a field's change, `brick:loading='$set("query")'`, also when that field's deferred value rides along another action, and for paths under it; and `.except`, `brick:loading.except="download"`, shows for every action but those. The compiler checks each target (the name, the arguments as JSON, the `$set` field against `state:`), and `.except` with no value is a compile error.
- `brick:show` plays `brick:leave` when it hides an element, and the new `brick:enter="classes"` when it shows one: the element is un-hidden with those start classes, which come off on the next frame so its transition plays in (`data-brick-entering` while it does, at most 2 s). The JS `show` command plays `brick:enter` too. Nothing plays on the first render or under `prefers-reduced-motion`.
- `brick.js(el, "hide('#x'); addClass('this', 'on')")` runs v18's client command list from code (a `brick.mount` hook, an effect handler, a stored attribute: `brick.js(el, el.getAttribute("data-on-close"))`), with `el` as `this`; a bad list throws, because it is code, not markup.
- `brick.find(type)` and `brick.all(type)` look stateful components up by component name (the file stem, `data-brick-name`); `brick.all()` lists every stateful component on the page.
- A valueless `brick:disable-with` disables the button while its action runs and keeps its label.

#### v21: server — cancel a job, clear flashes, check an upload

- **Cancel one background job**: `Jobs.Cancel(ctx, id)` and `Engine.CancelJob(ctx, id)` from Go; `Effects.CancelJob(id)` / `brick.cancel_job(id)` from an action, applied only after the action succeeded and its state was saved (a failed action cancels nothing), and before the action's own new jobs start, so "cancel the old export, start a new one" works in one action. An action may cancel only a job that an action of the same component started under the same session; a Go-started job, another component's or another session's is refused (`ErrJobNotYours`), reported through the `OnError` hooks, and keeps running. A job that already ended is a silent `ErrJobNotFound` from an action. A waiting job never runs; a running job's context ends with `ErrJobCancelled` as its cause. Either way it ends through `JobsOptions.OnError` with `ErrJobCancelled` and its topic is published, and `Run` returns `ErrJobCancelled` so a retrying queue can skip it. A `JobQueue` can cancel by implementing the optional `JobCanceller` (`CancelJob(ctx, id, may func(Job) error)`); one without it returns `ErrJobCancelUnsupported` rather than pretend. `Job` gains `Session` (the starting instance's hashed session). New errors: `ErrJobCancelled`, `ErrJobNotFound`, `ErrJobCancelUnsupported`, `ErrJobNotYours`.
- **`brick.clear_flash(level = None)`**: `Effects.ClearFlash(level)` records a `flash-clear` effect (`EffectFlashClear`) that dismisses the flashes on screen, every one or one level. The runtime emits `"flash-clear"` `{level}`, clears its default display and drops matching flashes being carried to the next page; the kit `Toaster` dismisses its toasts. A flash recorded later in the same action still shows. `brick.effect("flash-clear", fn)` replaces the handler, as for `flash`.
- **Per-file upload check**: `Options.UploadCheck func(ctx, UploadMeta, head []byte) error` runs on every proxied file after the declared accept, size and count checks and before `UploadSink.Open`, with the sniffed meta and the first `UploadCheckBytes` (512) bytes, so a refused file is never stored. `brick.RefuseUpload(message)` refuses with the message shown on the field (422, `ErrUploadRefused`, matching `ErrBadValue`, so a form without JavaScript shows it on the field too); any other error is a server failure. On a presign request it runs with a nil head (the claims only). It is an option, not a sink upgrade, so a host does not wrap its sink and hide `UploadRemover` / `UploadPresigner`.

#### v21: testing and the formatter

- `bricktest.LiveRoot.SubmitWith(form, button, values)` submits a form as if that submit button was pressed: a named button's `name=value` goes with the fields, as `FormData(form, submitter)` sends them, so a test can drive a form with "save" and "delete" buttons. The test fails on a button that cannot submit (`type=button` or `reset`, disabled, an image button, one outside the form).
- `brick.WithViewLog(*brick.ViewLog)` records the props each component call rendered with (loader output merged in) and its loader's own keys (`ComponentView.Loaded`), across a render, its Fill, action re-renders and lazy answers; without it a render pays one nil check per component. `bricktest.Live` attaches one: `live.Views("Card")` lists every render of a component, oldest first, and `live.AssertViewHas(t, "Card", "price", 42)` checks its latest render (after a `Call`, the action's), so a test can check a value reached the template when the markup never prints it.
- `brick.WithLazyInline()` makes `Fill` and `FillStream` render every `brick:lazy` island in place (every mode, nested ones too) with its state stored as usual, so `bricktest.Live(t, eng, page, brick.WithLazyInline())` sees a lazy island's content and can call its actions without a second request.
- `brick fmt`: `fmt.inline` in brick.yaml (and `-inline a,em,Icon`) names the elements and component tags whose content keeps the parent's indentation, so prose wrapped inside `<a>` or `<em>` is not pushed a level deeper. HTML names compare without case, component tags exactly. Absent, nothing is inline and the output is byte-identical to before. The language server's formatting reads the same setting.

#### v22: navigation — URL callbacks and fragment mode

- **Per-component URL callbacks**: `brick: {params: fn}` on a component with `query:` names `fn(state, props, params) -> state | [state, errors]`, where `params` is the component's own parameters as the address bar shows them. It runs when the instance is created and whenever the URL changes those fields without the component asking. A link or `brick.navigate` to the same page that changes only parameters owned by components on it is now a **patch**: no page fetch, `pushState`, and only the owning components re-render through the new `$params` built-in; Back and Forward over such entries send `$params` too. A correction the hook makes writes the URL back with `replaceState`. The hook never runs after the component's own actions. `params:` needs `query:` and must name a script function.
- **Navigation fragment mode**: site pages that load `nav.js` mark where the page sits in its layout (`<!--brick:page-->` … `<!--/brick:page-->`, `brick.WithPageMarks`, `brick.PageStartMark` / `PageEndMark`) and name the rest of the document with a fingerprint of its rendered bytes (`<meta name="brick-layout">`, the `Brick-Layout` header, `Vary: Brick-Nav`). `nav.js` sends it as `Brick-Nav`; when the next page's layout renders to the same bytes the answer is only the page (`Brick-Fragment: 1`), spliced between the marks so the layout's nodes are never touched. A different layout, a stale fingerprint, a streamed page, a POST or a page without marks gets the full page. On the kit showcase a docs navigation drops from 146.9 KB to 29.1 KB (20.5 KB to 6.2 KB gzipped). Pages without `nav.js`, `Site.Render` and `Export` keep their bytes.

#### v22: runtime — Modelable, server transitions, held keys, click details

- **Modelable components**: a stateful child declares `brick: {model: value}` and a stateful parent binds its own field with `<Stepper brick:model="qty">`; the parent's value flows down whenever it renders the child, and the child's own changes go up as a `$set` of the parent's field.
- `brick.transition(types)` / `Effects.Transition(types)` (`EffectTransition`, `TransitionNone`): an action chooses its own view transition (types, untyped with `""`, or `"none"` to skip), with or without `brick:transition` on the root.
- `brick:keydown.norepeat`: a held key runs its action once per press; its repeats are still matched, so no outer binding takes them.
- `brick:click.details` (also with `.outside`): the click's modifier keys, button, count and position as the action's last argument; `bricktest` `ClickWith` and `ClickDetails`.

#### v22: push — presence

- **Presence**: `brick: {listen: {presence: "room:{{ .Props.id }}"}}` and `{{ .Presence "room:7" }}` (`PresenceList{Total, Entries}`, each `PresenceEntry{ID, Data, Conns}`) show who is on a topic and refresh every viewer when someone joins or leaves. Identity is the host's (`PushOptions.Presence.Identify`); by default an entry is an anonymous random id with no data. Entries leave when the stream closes and lapse after `PresenceOptions.TTL` (90 s) if a server dies. `MemoryPresenceStore` for one server, `contrib/push-redis` `NewPresenceStore` across servers; a presence component under a cross-server `Broadcaster` without a shared store fails to render with an error naming it. `.Presence` answers only for topics the component declares, and `AuthorizeTopic` is asked about presence topics too. Limits are named constants (`DefaultMaxPresenceEntries`, `DefaultPresenceListMax`, `DefaultMaxPresenceTopics`, `MaxPresenceIDLen`, `MaxPresenceDataKeys`, `MaxPresenceDataLen`, `MaxPresenceTopicLen`).

#### v22: site — dynamic output pages and per-request pages

- Dynamic output pages: `content/tags/[tag]/feed.xml.html` renders `/tags/go/feed.xml` for each value of its `brick: {paths:}` list, in `brick serve` and `brick build`. Parameters go in directories; a `[param]` in the file name is refused. `.json`, `.js`, `.css` and `.csv` output pages stay refused.
- Per-request pages: `brick: {per_request: true}` renders a page on every request instead of from the page cache, with `site.Options.Request`'s values (`.Ctx`), and sends `Cache-Control: private, no-cache` (`site.PerRequestCacheControl`) unless its loader sets one; its loader's redirect, error status or `brick.not_found()` is sent `private, no-store`. `brick build` skips such pages with a warning, prints `skipped <url>` and lists them in `ExportReport.Skipped` (and `skipped` in `brick build -json`); `Route.PerRequest` marks them for hosts with their own cache.

#### v22: components — sibling stylesheets and the `:prop` shorthand

- A component's sibling stylesheet: `components/Card.css` next to `Card.html` ships like a `<brick:style>` block, global by default or scoped with `brick: {css: scoped}` (or `inclusive`); it shares the component's one content-hashed sheet (file first, inline blocks after) and live-reloads on edit. `StyleBlock.Sheet` names the file for `Options.StyleTransform`.
- `:prop` shorthand: `<Card :post />` passes `$post`, the variable of the same name; a missing variable, a non-identifier name and the `:$post` spelling are compile errors that name the fix.

#### v22: forms — form objects and regions

- Form objects: `.Form` gives each state field one value in templates (`FormField`: `.Name`, the path `brick:model` takes, `.ID`, `.Value`, `.Error`, `.Touched`, `.Invalid`), built from the component's state, errors and touched paths; `.Items` and `.Fields` walk list and dict fields, so a wildcard-rule list reads `todos.2.title` without assembling paths by hand.
- Regions: an action replaces, appends to or prepends to a `brick:ref` + `brick:ignore` element of its component with `brick.region(ref, op)` / `Effects.Region(ref, op)` (`EffectRegion`, `RegionReplace`, `RegionAppend`, `RegionPrepend`); the content is that element in the action's own render, and ordinary re-renders leave the region alone.

#### v23: method links

- **Method links**: `<a href="/posts/7" brick:method="delete">` sends a DELETE (or `post`, `put`, `patch`) instead of a GET. A plain left click builds a hidden form to the href and submits it natively; a verb other than POST rides in the `_method` field (`brick.MethodField`), and `brick.MethodOverride(h)` turns a same-origin, form-encoded POST carrying it back into PUT, PATCH or DELETE for the host's router (a cross-site post, a multipart or JSON body and any other verb pass through untouched). `brick:confirm` asks first and `brick:disable-with` marks the link busy, in any file; `brick.methodFormWith((form, link) => …)` adds the host's own CSRF token, since brick has no token for plain forms. Modified clicks (new tab) and visitors without JavaScript get the link's ordinary GET, so a GET route must never change anything. The compiler refuses `brick:method` on anything but an `<a>` with an href, an unknown verb, a modifier, and `brick:confirm.prompt` beside it; a page with a method link loads the runtime even without client code. Navigation never fetches a method link as a page, and `brick:prefetch` (and the speculation rules) skip it. `examples/methodlinks`, `task test:v23:chrome`.

#### Diagnostics

- `brick.DiagnosticOf(err, file)` returns the structured `Diagnostic` (file, line, column, code, bare message) for an engine error, so hosts can dedup or format errors without parsing the position prefix.

#### CLI

- `brick build` and `brick serve` take `-keep /a/,/b/`, the command-line form of `site.Options.KeepPaths`: root-absolute URL prefixes the `-base` rewrite leaves alone.

### Changed

- `brick:prefetch` waits 65 ms of hover before prefetching (a pointer crossing a menu no longer fetches every link), and prefetches at once on keyboard focus and on press.
- `brick:keep`, which the runtime has read since v6, is now accepted by the compiler on plain elements; before, it was refused as a reserved attribute.
- Navigation saves its own scroll positions and sets `history.scrollRestoration = "manual"`.
- The `action-error` event's detail is `{action, message, root, id, status}` (v9); before, it carried only the action and the message.

- **Breaking:** `StateStore.Put` returns the handle the page carries (`Put(ctx, inst) (string, error)`): the store makes the handle, not the engine. A custom store generates its own key, or returns the sealed instance.
- **Breaking:** an action's request-scoped `.Ctx` (values given with `Provide`) is no longer stored with the instance; it comes from `Options.ActionRequest` on every action (the site layer sets it from `site.Options.Request`).
- **Breaking:** `brick build` of a site with stateful components needs `BRICK_SECRET`: an export's sealed state must open on the action server.
- The site layer seals state when `StateKeys` is set, and otherwise keeps the memory store with a warning on the first stateful response. Responses with stateful islands are sent `Cache-Control: private, no-cache`.
- **Security (v7):** `$set` and `sets` never replace a whole dict or a list of dicts (set the parts by path; add rows with an action), and a field declared `null` takes a scalar or null only. Before, a client could write any value into such a field, including keys the component never declared.
- A refused `$set` value is now **422** (`ErrBadValue`), the same as a refused `sets` entry; it was 400. A malformed `$set` call (wrong argument count, a non-string field) stays 400.
- Remote libraries may add component names to every page, which v3 ruled out (a remote kit was usable only through explicit `use:` imports). v4 keeps the reason for that rule — a stranger's names must not shadow the project's own — by placing libraries below the project in precedence and logging every shadowing.
- **Behaviour (v14):** `brick:keydown.<key>` now matches only when no modifier key is held: `brick:keydown.enter` no longer fires for shift+enter or ctrl+enter, so a chat box can send on Enter and leave shift+enter to type a newline. A bare `brick:keydown` (no key) still fires for every key with any modifiers. No attribute in the kit or the examples relied on the old behaviour.
- **Behaviour (v15):** An error boundary no longer contains a loader's answer (`brick.not_found()` included): its fallback would have sent the page around it with status 200. `Engine.Fill` likewise returns an island's answer at once, ignoring the boundary fallback and the Dev error block.
- **Behaviour (v15):** Answers are never reported to `OnError` hooks, and `brick check` / `Site.Check` no longer report a page whose loader redirects or answers an error status.
- **Behaviour (v15):** An action whose component's loader redirects during the re-render (signed out since the page loaded) answers with that redirect as its one effect and no HTML; a loader's `brick.error` keeps its status on the action response (`brick.ActionStatus`), with the author's message, never a file path. `brick.redirect` inside an action function is unchanged (a client navigation); `status=` is refused there.
- **Breaking (v15):** `content/error.html` is no longer an ordinary page: it renders `brick.error` answers, so a site that had one at `/error/` loses that URL. Rename the file to keep the page.
- **Behaviour (v19):** topics starting with `brick:` are engine-owned: `ValidTopic` refuses them, so `brick: {listen:}`, `brick.publish`, `Engine.Publish`, `Effects.Publish` and job topics cannot use them, and the error says the prefix is reserved. A custom `Broadcaster` that filters topics must use `ValidBroadcastTopic`, not `ValidTopic`.
- **Behaviour (v20):** the server refuses the same reserved event names the runtime does. `brick.dispatch`, `$dispatch` and `brick: {on:}` / `brick:on:` now also refuse `action-cancelled`, `action-retry`, `island-loaded`, `island-error` and the new `errors-cleared`, which the browser already refused (a dispatch of one was recorded and then dropped, and a listener on one never ran). A test keeps the Go list equal to the runtime's.
- **Behaviour (v21):** a `brick:show` element that also carries `brick:leave` now plays its exit before it hides (and `brick:enter`, when it has one, as it shows); before, `brick:show` toggled `hidden` at once and only a JS `hide` played the exit. An element without those attributes hides and shows exactly as before. `flash-clear` joins the reserved event names, so `brick.dispatch`, `$dispatch` and `brick: {on:}` refuse it.

### Fixed

- `brick check` printed each page error twice, the second with its file, line and column repeated; it now reports each once.
- `use:` now accepts any extension registered in `Options.DataFormats`; it refused everything but `.json`, `.yaml` and `.toml`.
- A page whose only interactive part is a stateful component (no client code, navigation off) now links the browser runtime, including a component chosen by `<brick:render>` at fill time.
- `brick.region` and `brick.skip_render` are refused in either order.
- Reserved event names now include every name the runtime emits (`upload-progress`, `upload-done`, `upload-error`, `push-error`, `refreshed`, `dirty`, `clean`), so an action cannot fake them.
- An unknown `brick:loading` target reports the attribute's line and column.
- `Route.Path` and `brick routes` name the language variant file actually rendered.
- A page or layout frontmatter key that shadows a key from its `load:` function is now warned about (the frontmatter still wins).
- The `statetest` conformance suite no longer ignores its own setup errors.
- `arith` no longer silently computes min for an unknown operator.
- Dev-server watchers now stop together when one fails to start.
- `brick.submit`, `brick.rows` and `brick.stream` now find a `brick:ref` placed on the component's root element itself (v10).
- A site page, island or playground render that fails (a component that does not compile, a failing loader) is now logged to `site.Options.Logger` with its file and line (v19). Before, Prod sent a bare 500 and nothing reached the log, so the cause was visible only by calling `Engine.Render` directly; Dev still shows it inline as well. A plain 404 is not logged.
- bricktest: a renderless action (`brick.skip_render`) no longer blanks the component in a `LivePage`; the held HTML stays, as the runtime keeps the element (v20).
- A morph during a `brick:leave` exit that ends in hidden (a JS `hide`, and now `brick:show`) inserted a second copy of the element, because the morph treated every leaving element as removed; now only an exit that ends in removal is skipped, and the hiding element is patched in place with its exit classes kept (v21).
- An element a morph dropped while it was hiding with `brick:leave` stayed in the page, hidden; it now leaves for good (v21).
- A page whose only live part is a `brick: {listen:}` component now loads the runtime; with navigation off it shipped no script, so push never connected (v22).
- A bad `brick:` frontmatter value in a component reached through a page is now reported at that key's line in the component file, with code `frontmatter`; it was reported at line 0 as an import error (v22).
