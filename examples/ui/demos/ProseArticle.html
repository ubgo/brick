Rendering on the server, again

For a decade the default answer to "how should this page render?" was in the browser. The pendulum is swinging back — not because client rendering failed, but because most pages never needed it. Read the original proposal.

What changes

A component is a file. It renders to HTML on the server, ships its CSS once, and adds JavaScript only where the page needs behaviour:

  • No build step. Save the file, reload the page.
  • No hydration. Client code enhances markup that is already there.
  • Progressive by default — every component works with JavaScript off.
    • A dialog is a native <dialog>.
    • A dropdown is a <details>.
The fastest JavaScript is the JavaScript you never send.
