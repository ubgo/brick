Live interactivity

{{ .Params.description }}

Each demo is one stateful component with no JavaScript of its own. The feed loads eight more rows whenever the sentinel under the list scrolls into view (brick:intersect.margin.100px="more"); the runtime re-arms the sentinel after every load, and the template's {{ "{{ if }}" }} stops it at the end. Every row carries brick:key, so loading or reversing keeps each row's element, and brick:transition on the root animates the reorder where the browser supports view transitions.

.optimistic works on a literal $set or $toggle only: the browser flips the signal at once, so brick:show changes before the request returns, and puts it back if the action fails. The count is server-rendered and follows the answer.

A list whose filter and page live in the URL: brick: {query: {q: {as: fruit}, page: {history: push}}}. Open the page with ?fruit=berry and the list starts filtered; typing replaces fruit=, paging pushes a history entry, and Back restores the previous page in place, without a page fetch. init: counts the catalogue once when the instance is made, updated: trims the search and sends a new search back to page 1, and Clear is $reset("q", "page"), which puts both fields back to their declared values.

A slow panel that does not hold up the page: brick:lazy="visible" on the call renders a placeholder holding a sealed ticket, and the enclosing boundary's loading block is what shows until the panel scrolls into view. The runtime then redeems the ticket at /_brick/island and swaps the answer in. The panel's loader takes about a second; the page above it never waits for it.

A slow panel streamed into the page's own response: brick:lazy="stream" sends the page at once with the boundary's loading block, and the panel's HTML follows in the same response when its loader finishes (about a second), with no second request.

Brickbot streams its reply: the action calls brick.stream("answer", word) for each word, and every chunk is appended to the brick:ref="answer" element as text while the request is still running. When the action returns, its normal render lands and replaces the streamed text.

A live board over server push: the board declares brick: {listen: "demo:notes"}, and posting runs an action that inserts the note and calls brick.publish("demo:notes"). The page holds one EventSource on /_brick/events, opened with the listen token the server sealed into the board's root, so the browser can only hear topics its page was rendered with. When the topic is published, every open board, in this window or any other, runs a quiet $refresh and reads the notes again through its own render: the event carries the topic and nothing else. Open this page in a second window and post a note.

Background jobs: Run report answers at once; the job works for a second and a half after the response, then publishes demo:jobs, and this component, which listens to that topic, refreshes and shows the result. The failing button shows the error path: the job's error is recorded and the component shows it.

Client commands for the small things that need no server: brick:js.click='toggle("#menu"); toggleAttr("this", "aria-expanded", "true", "false")' opens the menu, brick:js.click.outside on the wrapper and brick:js.keydown.escape.window close it, and the notice's ✕ runs hide("closest .v18-panel"). The list is closed (show, hide, toggle, classes, attributes, focus, dispatch) and every argument is a literal, so this is not a client-side state language: state still changes only in actions. An element with brick:leave="classes" plays those classes before it is hidden or removed.

Rows that fade out as they are deleted, and a rename that asks first. Each row carries brick:leave="v18-out", so when the action's morph drops it the runtime adds the class, waits for the transition (at most two seconds, not at all under reduced motion) and only then removes it. Rename is brick:confirm.prompt="New name?" with brick:click="rename(3)": the visitor's answer arrives as the action's last argument, rename(state, props, id, name), and Cancel sends nothing. brick.promptWith(fn) swaps the browser's prompt for your own dialog.
