Patterns & gotchas

{{ .Params.description }}

1Mounts must be idempotent A client module's mount runs again whenever an action's patch replaces its element. Set up from the markup you are given, never assume "first time", and return a cleanup for every listener you add outside the element. brick.mount("Chat", (el) => { const onKey = (e) => { … }; document.addEventListener("keydown", onKey); return () => document.removeEventListener("keydown", onKey); }) 2Dialog open state belongs to the server A dialog an action opens must be closed through an action too, or the next re-render (a search, a poll) opens it again. closeAction reports every close — Escape, ×, Cancel, the backdrop. … 3Give every flash toast a new id The Toaster shows an id once per page. Count flashes in state and put the count in the id; clear the text in every other action. {{ with .State.flash }}{{ end }} 4Action arguments are JSON brick:click arguments are parsed as JSON, so a string needs double quotes — write the attribute in single quotes. Numbers need nothing. A call brick cannot parse is an error when the file is read. 5Starlark's % has no width flags "%02d" fails at run time with "unknown conversion %0" — inside an action, where the page only sees an action error. Pad by hand. def _pad(n): return ("0" + str(n))[-2:] # 9 -> "09" 6A display rule beats [hidden] hidden is only display: none in the browser's stylesheet, so any class that sets display wins over it. Theme guards every kit class; a class of your own needs its own line. [class*="bk-"][hidden]:not([hidden=until-found]) { display: none !important; } /* Theme */ .auth-form__loading[hidden] { display: none; } /* yours */ 7Conditional children and .Children A tag inside {{ "{{ if }}" }} is listed in its parent's .Children even when the condition is false. That only matters for components that read .Children (Tabs, AvatarGroup); brick warns only for those. When it does matter, move the condition into a small component of its own. {{/* renders nothing for id 0 */}} 8Per-request values live in islands A page renders once and may be cached; only an island (a stateful component, or brick: {island: true}) renders per request. The query string, the user, the time — read them there, through inject. inject: query: {default: {}} # .Ctx.query.mode in the template 9Component output is trimmed brick trims whitespace at the edges of a component's output, so an inline component sits in running text with no stray spaces and needs no {{ "{{- -}}" }} markers. Run task ui:test, then reload. → Run task ui:test, then reload. 10+ becomes &#43; in text html/template escapes + in text. The page shows "+2 more"; a test that searches the raw HTML must look for "2 more" or "&#43;2 more". mustContain(t, "Sep 30", cell, "2 more") 11Quote YAML flow values with punctuation Inside {…} a comma ends the value, and ? or : can start a key. A question or a sentence with a comma must be quoted, or the frontmatter fails to parse. # breaks: the comma and the ? end the value - {q: Do I need Go?, a: Only to host it} # works - {q: "Do I need Go?", a: "Only to host it."} 12Listen on the form, not on document The runtime handles brick:submit with a listener on document, so register yours on the form or the component: those run before it, while the fields are still there to read or clear. Chat clears its composer this way. el.addEventListener("keydown", (e) => { if (e.key === "Enter") form.requestSubmit(); });
