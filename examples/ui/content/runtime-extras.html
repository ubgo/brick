Rows, hand-offs and declarations

{{ .Params.description }}

Row streams: the feed keeps no rows in its state. Each action calls brick.rows("feed", component = "RuntimeRowsItem", items = […], at = "top", limit = 5), the server renders each item through that component (so what you type arrives escaped), and the runtime inserts the rows into the brick:ref="feed" list, matched by brick:key. The list carries brick:ignore, so the component's own re-render leaves the rows alone, and limit trims the oldest row off the bottom. last is declared brick: {temporary: [last]}: the render that answers an action sees the rows it sent, then the instance is saved with last back at [], so Re-render shows 0. Clear is op = "reset".

Regions: a list written inline in the component's own template that grows instead of being replaced. The brick:ref="feed" list carries brick:ignore, so ordinary re-renders leave it alone; brick.region("feed", "append") appends the same element's children from the action's render, "prepend" puts them first, and the default "replace" refreshes a region only when an action names it (Recount). Unlike rows there is no row component and no keys; Re-render updates the text outside the regions and nothing inside them.

A hand-off to a classic form post: the action checks the name like any action, and only when it is valid calls brick.submit("classic"). After the morph the browser submits the brick:ref="classic" form natively to /demo/sign-in, a plain Go handler that sets a cookie and answers 303, which only a top-level post can turn into a signed-in page. Submit is terminal, like a redirect.

Recovering from a 500: Break it runs an action that fails on purpose, and the showcase's host answers that failure as a server fault (a 500; the engine's default for a script failure is 422, which the visitor can correct). The runtime fires action-error with the component's root and the status; this component's client code shows a notice, and its button calls brick.reloadComponent(el), which fetches a fresh render of just this component and morphs it in. The count starts over from its declared value.

A batch loader: RuntimeUserCard names brick: {load_many: users.cards} instead of load:. Five cards in a {{ "{{ range }}" }} wait until the page has run, then the loader is called once with the four distinct inputs and answers a list in the same order. Each card prints how many inputs that call carried: 4 on every card means one call answered them all; a loader called per card would print 1.

Declared slots: RuntimePanel lists the blocks it takes under brick: {slots:}, with required:, doc: and examples:, and its props carry doc: too. A call that leaves out the required title, or passes a block the panel does not declare, fails at compile with the caller's file and line. brick docs (and Engine.ComponentDocs) print the props and slots with their docs.

An element name from data: tag writes the whole start tag and endtag the close, so a heading's level can come from state or a prop. They write only elements without URL, script or raw-text content, refuse on*, URL and style attributes, and escape every value.

A modelable child: V22Stepper names its value as its model with brick: {model: value}, and the cart binds its own qty to it with <V22Stepper brick:model="qty">. The stepper's buttons change the cart's total; the cart's reset comes back down into the stepper. Each change makes one trip each way: up as a $set of the parent's field, down when the parent renders.

An action chooses its own view transition: brick.transition("slide") names the type CSS styles with :active-view-transition-type(slide), and brick.transition("none") morphs without one, though the root opts in with brick:transition.

A held key: brick:keydown.norepeat.enter runs once per press, however long Enter is held; without .norepeat the binding repeats with the key, as before.

Click details: brick:click.details passes the click's modifier keys, button, count and position as the action's last argument. Without .details nothing about the click is sent.
