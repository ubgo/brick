Building an app

{{ .Params.description }}

Every app in the sidebar (Contacts, Invoices, Inbox, Chat, Calendar…) has the same four parts, and everything but the page and the Go seed lives in one folder, apps/<app>/. The browser holds nothing but a sealed handle it cannot read or change, every click is an action, and the reply is the component re-rendered and patched in place. Contacts is the worked example below; the excerpts are copied from its files.

 content/apps/contacts.html the page: layout, AppShell, the app component apps/contacts/ContactsApp.html one stateful component: state, markup, dialogs, toasts apps/contacts/contacts.star queries and actions, in Starlark demodb/db_contacts.go the table and a deterministic seed (host Go code)

1 · The page: layout, AppShell, AppNav

layout: app drops the docs chrome. AppShell gives the sidebar, the sticky top bar and the scrolling main area; AppNav is the shared app menu, told which entry is current. The page itself holds no logic: it places the app component and a Toaster.

2 · One stateful component

All UI state — search, filter, sort, page, selection, the open form, the toast — is declared in state:. use: imports the app's Starlark file under a name. Because the component has state it renders per request (it is an island), and the page around it stays cacheable.

 --- use: contacts: ~/apps/contacts/contacts.star state: q: "" status: all sort: created dir: desc page: 1 pageq: "" per: 10 selected: [] form: {open: false, id: 0, name: "", email: "", company: "", role: "", status: lead} detail: 0 ---

3 · Reading data: one script function

The template asks Starlark for everything the page shows in one call, then ranges over plain values. The function takes the state, so the query follows the filters.

 {{ $v := contacts.view .State }} def view(state): """Everything the page shows that comes from the database.""" filt, q = _filters(state) total = db.query(Q_COUNT, *filt)[0]["n"] page, pages = _page(state, total) …

4 · SQL is literal

db.query and db.exec accept only SQL written as a literal or a module-level constant, so a value can never become SQL. A dynamic ORDER BY therefore cannot be built by concatenation: write one fixed query per order and choose between them with an if-chain. Filters that may be off are always present and switched off by their arguments (? = 'all' or status = ?).

 Q_NAME_ASC = "select id, name, email, company, role, status, created from contacts where (? = 'all' or status = ?) and (? = '' or name like ? or …) order by name collate nocase asc, id asc limit ? offset ?" … def _rows(key, args): if key == "name_asc": return db.query(Q_NAME_ASC, *args) if key == "name_desc": return db.query(Q_NAME_DESC, *args) … return db.query(Q_CREATED_DESC, *args)

5 · The host wiring

Scripts have no clock, network or files. The Go host grants exactly what the apps need: the database (writes only because DBExec is on), a today() built-in for stamping new records, sanitize_html sharing one HTML policy with the template's sanitize, and pause, a stand-in for slow work that the lazy panel and the streamed reply on the Live interactivity page use. Request hands islands and actions per-request values (step 11). StateKeys, read from BRICK_SECRET, seals each app's state into its page, so an open app keeps working when the server restarts.

 sc, err := scriptstarlark.New(scriptstarlark.Options{ Globals: starlark.StringDict{"today": today, "sanitize_html": sanitizeHTML(policy), "pause": pause}, DB: db, DBExec: true, }) … keys, err := demosite.StateKeys(os.LookupEnv, dev, log.Printf) … s, err := site.New(ctx, site.Options{FS: root.FS(), Engine: eng, Dev: dev, Request: requestValues, BasePath: base, KeepPaths: keep, StateKeys: keys})

6 · Actions

An action is a Starlark function (state, props, args…) that returns the new state. The page calls it three ways: brick:click="contacts.goto(3)" (arguments are JSON), brick:submit on a form (the fields arrive as a dict), and brick:change on a control (its value). brick:model writes one state field directly — no action needed — and .debounce.300ms waits for a pause in typing. brick:loading shows while a request runs.

 def goto(state, props, page): return dict(state, page = int(page), pageq = state["q"].strip())

7 · Validation: [state, errors] and Field

An action that returns [state, errors] re-renders with .Errors set for that render only. Keep what the visitor typed in state so the form comes back filled in. <Field :error=".Errors.name"> shows the message and wires aria-invalid and aria-describedby to the control; an empty error shows nothing, so the same markup serves the first render.

 errors = {} if len(f["name"]) < 2: errors["name"] = "Enter a name of at least two letters." … if errors: return [dict(state, form = f), errors]

8 · Dialogs opened by the server

Whether the form is open is state: edit(id) fills form and sets open, and the Dialog renders with :open. When the visitor closes it (Escape, ×, Cancel), closeAction tells the server, so the next re-render does not open it again. A failed save keeps it open with the errors inside.

9 · Messages and events: brick.flash and brick.dispatch

An action returns the new state and may also record effects: things the browser does after the re-render. brick.flash(message, level) shows a message (the page's <Toaster> listens to flashes and shows each as a toast of that variant), so no state field has to carry it. brick.dispatch(name, data) tells every other component on the page that something happened: the topbar's <ContactCount> lists contact-added and contact-deleted under brick: {on:} and runs $refresh on each, so the count stays current although neither component names the other.

 db.exec(X_DELETE, id) brick.dispatch("contact-deleted", {"ids": [id]}) brick.flash("Deleted " + found[0]["name"] + ".", "success") state: {} brick: on: contact-added: $refresh contact-deleted: $refresh

Element ids are built from $.ID, the instance's own id, so two copies of the app can share a page without one copy's buttons opening the other's dialogs.

10 · Confirm before destroying; paginate with an action

ConfirmDialog's action runs a server action when the visitor confirms. Pagination's action turns every page link into brick:click="contacts.goto(N)"; its href stays as the no-JavaScript fallback.

11 · Per-URL records: islands read the query

The page is rendered once; a stateful component (an island) renders per request. The host's Request hook provides the query string, and an island opts in with inject. The sign-in form uses it to open on the register form for /apps/auth/?mode=register — only while its state is fresh, so actions stay in charge afterwards.

 func requestValues(r *http.Request) []brick.RenderOption { q := map[string]any{} for k, v := range r.URL.Query() { if len(v) > 0 { q[k] = v[0] } } return []brick.RenderOption{brick.Provide(queryKey, q)} } --- inject: query: {default: {}} state: touched: false mode: signin … {{- $mode := .State.mode -}} {{- if and (not .State.touched) (eq (print (index .Ctx.query `mode`)) `register`) }}{{ $mode = `register` }}{{ end -}}

12 · Testing an app through /_brick/action

A test drives the component exactly as the browser does: read the state handle and token from the rendered page, POST an action as JSON (one shared helper, postAction, builds the request every app test sends), and keep the new handle and token the patch carries. Assert on the returned HTML, and on the database when the action writes.

 body, err := json.Marshal(map[string]any{"handle": handle, "token": token, "action": action, "args": args}) … req := httptest.NewRequest(http.MethodPost, actionPath, bytes.NewReader(body)) req.Header.Set("Content-Type", "application/json") req.Header.Set("Brick-Action", "1") code, out := postAction(s.t, s.h, s.handle, s.token, action, args...) … if m := landStateRe.FindStringSubmatch(out); m != nil { s.handle = m[1] }

13 · Determinism

The same input must give the same bytes, or tests and caches lie. The seed counts forward from a fixed epoch, never from the clock; apps that need "today" in a view use a constant (Calendar's TODAY = "2026-09-27"); today() is only for stamping records an action creates, and tests that read those stamps derive the expected value rather than hard-coding a date.

 // seedEpoch is the first seeded date. Seed rows count forward from it, so // every run produces the same rows and the pages that show them the same // bytes. var seedEpoch = time.Date(2026, time.January, 5, 0, 0, 0, 0, time.UTC)
