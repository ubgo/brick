File uploads

{{ .Params.description }}

How it works

  • brick: {uploads:} names the state fields that take files, with the accepted types, the size limit and, for a list field, how many files it holds. The field is null for one file or [] for several.
  • brick:upload="avatar" on a file input (here through the kit Dropzone) sends each chosen file as its own request. The server counts the bytes as they stream, sniffs the type from the content, and hands them to the host's UploadSink.
  • The ref lands in state. When the sink has stored the file, .State.avatar holds a small dict: id, name, type, size and url. The bytes never enter state, and scripts never touch files.
  • Without JavaScript. A file input with brick:upload inside a brick:submit form uploads with scripts off too: the form gets enctype="multipart/form-data", and the engine streams each file part into the same sink with the same limits before the form's action runs. A refused file stops the post; the page comes back with status 422 and the reason in .Errors.avatar.
  • Progress and cancel. <progress brick:upload-progress="avatar"> fills as the file is sent; $cancelUpload("avatar") aborts it; $removeUpload("avatar", id) asks the sink to delete the file and clears the field.
