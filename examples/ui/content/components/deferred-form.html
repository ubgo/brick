Deferred forms

{{ .Params.description }}

How it works

  • brick:model.defer updates brick:text and brick:dirty in the browser at once but sends nothing. The values wait and ride as sets with the next request of the component, here the submit, so save sees them already in state.
  • Checkbox groups. tags starts as a list, so the engine marks it in data-brick-arrays and the boxes bound to it send the checked values as a list.
  • Loading. brick:disable-with swaps the button's label while it saves, data-loading lands on the button and the form, and brick:loading.delay="save" appears only when save takes longer than 200 ms.
  • Confirm. brick:confirm asks before clear runs; the browser's dialog by default, or any dialog registered with brick.confirmWith(fn).
