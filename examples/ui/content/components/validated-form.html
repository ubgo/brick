Validated forms

{{ .Params.description }}

How it works

  • brick: {rules:} maps a state path to its rules: required, min, max, email, url, pattern, in and same. An unknown rule or a path that is not in state: is a compile error. messages: replaces one rule's message.
  • Touched fields. A field becomes touched when the browser first sends it. With brick:model.lazy that is when you leave it, so a half-typed address is not flagged while you type. Errors are computed at every render from the state, the rules and the touched set, so confirm re-checks when password changes.
  • Submit. brick.validate() touches and checks every field and returns the errors; the action returns [state, errors] to stop. After a successful sign-up, brick.untouch() clears the touched set so the emptied form does not light up with "required".
  • Action errors win. An error the action returns (the taken address) replaces the rule error for that field for one render.
  • Form objects. .Form.email is one value per field: .Name (the path brick:model takes), .ID (for label for=), .Value, .Error, .Touched and .Invalid. .Items walks a list and .Fields a dict, so the third todo's title is todos.2.title, the same path its todos.*.title rule reports under.
